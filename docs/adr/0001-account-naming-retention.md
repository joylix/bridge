# ADR-0001：账号注册、命名规则与数据留存

- 状态：已接受
- 日期：2026-10-25
- 决策人：产品 / 开发
- 关联：`docs/桥牌软件需求评审与开发建议.md` 0.4、0.5、0.6、P0-5、P0-13、P0-14、P0-15、P0-16

## 背景

原 SRS V0.4 采用“输入昵称即入室、匿名临时 userId”的模型，同时又要求系统管理员账号、最近对局、永久回放。现决定改为注册制，并把对局数据留存期定为 1 年。该变更影响账号模型、认证、昵称/用户名规则、对局历史归属、导出与回放权限，以及审计/隐私边界。

## 决定

### 1. 注册与登录

- 注册字段：邮箱、用户名、昵称、密码。
- 邮箱：必填、唯一、规范化为小写、可修改、**暂不验证**；预留 `emailVerifiedAt`。
- 登录：**用户名 + 密码**；邮箱不作为登录名。
- 忘记密码：V1 仅管理员重置（生成临时密码，首次登录强制修改）；不做邮件自助找回。
- 管理员：单个 `admin` 引导账号；初始密码从环境变量/首次启动生成，不入库明文、不进 Git；首次登录强制改密。公网部署禁止使用固定简单密码。
- 会话：httpOnly + Secure + SameSite=Lax Cookie；7 天，记住我 30 天；允许多设备，但同一房间只能占一个座位。
- 注册风控：图形验证码 + 每 IP 每小时 5 次注册 + 登录失败锁定；内网演示可关闭。

### 2. 用户名（登录标识，公开不可见）

- 长度 **3–12 位**。
- 只允许字母、数字、下划线，且以字母开头：`^[A-Za-z][A-Za-z0-9_]{2,11}$`。
- 归一化：`NFKC` + 转小写 + 去首尾空白后查重；`Alice`、`alice`、`Ａlice` 视为同一用户名。
- 保留名（大小写不敏感）：`admin`、`administrator`、`support`、`system`、`root`、`bridge`、`null`、`undefined` 等。
- 用户不可修改；管理员可纠正明显 typo，必须填写原因并写审计，不改变 `userId`。
- 只对本人和管理员可见；公开界面只显示昵称。

### 3. 昵称（公开显示名）

- 长度：**至少 2 个字符，最多 12 个显示宽度**。汉字/全角按 **2**，ASCII 字母/数字/下划线/连字符/空格按 **1**；即最多 **6 个汉字**或 **12 个英文字母**，混合时总宽度不超过 12。emoji 不支持。
- 宽度按 `NFKC` 归一化后的字符串计算（全角 `Ａ` → `A`，按 1 计）。
- 允许中文、英文字母、数字、下划线、连字符、单词间单个空格；不允许首尾空格、连续空格、控制字符、零宽字符、emoji。
- 归一化：`NFKC` + 去首尾空白 + 折叠连续空格 + 大小写不敏感后查重；保留显示大小写。
- 唯一性：**昵称全局唯一**；与用户名是两个独立命名空间；两者都禁用保留名。
- 敏感词过滤；管理员可强制改名。
- **改名次数：终身最多 3 次**。注册时的初始昵称不计次；失败/校验不通过不计次；管理员强制改名不计入用户的 3 次。
- **改名冷却：24 小时**；成功后 `nicknameChangeCount + 1`。
- **对局中禁止改名**：用户处于 `starting / playing / paused` 的盘中且已落座时不可改；大厅、等候区、旁观时可改。
- **旧昵称保留 30 天**：改名后进入保留表，30 天内其他账号不可使用；本人可改回，但仍消耗一次改名次数。30 天后释放。
- 账号注销/封禁：当前昵称保留 30 天后释放；历史改名记录保留在审计中。
- 日志/回放/成绩单存**当时昵称快照**；个人资料页显示当前昵称。

### 4. 查重与并发

- 客户端可做 300ms 防抖的可用性提示；**最终以服务端唯一约束为准**。
- 并发注册/改名只能有一个成功，其余返回 `409` + 明确错误码。
- 建议统一 `NameRegistry` 表：

```text
NameRegistry
  kind (username|nickname)
  normalized
  ownerAccountId
  status (active|reserved)
  reservedUntil
  UNIQUE(kind, normalized)
```

- 可用性查询接口限流，防止批量枚举昵称。

### 5. 账号数据模型

```text
Account
  id, email, emailVerifiedAt?, passwordHash,
  username, usernameNormalized,
  nickname, nicknameNormalized,
  nicknameChangeCount, nicknameChangedAt,
  role, status, createdAt, lastLoginAt

NicknameChange
  accountId, oldNickname, newNickname,
  changedAt, actorType (user|admin), reason
```

### 6. 数据留存与导出

| 数据类型 | 保留期 | 说明 |
|---|---|---|
| 对局事件/回放/成绩单 | 盘结束起 365 天 | 到期前 30 天提醒可导出 |
| 管理员审计日志 | 至少 3 年 | 不可由管理员删除 |
| 牌室/大厅聊天 | 90 天 | 敏感词/举报证据可单独留存 |
| 登录/IP/安全日志 | 180 天 | 限流、封号、争议调查 |
| 账号资料 | 至注销或 2 年未登录 | 连续未登录先提醒 |
| 备份 | 滚动 30 天 | 删除数据可能短暂存在于备份 |
| 用户导出文件 | 用户自行保管 | 不受服务端留存控制 |

- 对局/成绩单/回放导出：JSON 事件流 + PBN + CSV 成绩单（UTF-8 BOM）；单盘同步、全量异步。
- 玩家只能导出自己参与的对局；管理员导出需审计。
- **导出/回放时点**：同一 `Deal` 的所有 `TableBoard` 完成后才开放；整盘在 `Session` 结束后开放；对局中禁止导出当前未完成牌。参赛玩家在对局中不能看到另一桌的定局/结果/进度；跨桌信息只给旁观/转播并延迟。
- 注销：用户可申请注销，30 天冷静期；对局数据按 1 年策略匿名化/删除。

### 7. 错误码

`USERNAME_INVALID` / `USERNAME_TAKEN` / `USERNAME_RESERVED`
`NICKNAME_INVALID` / `NICKNAME_TAKEN` / `NICKNAME_RESERVED`
`NICKNAME_COOLDOWN` / `NICKNAME_CHANGE_LIMIT` / `NICKNAME_LOCKED_IN_SESSION`

## 后果

- SRS 需升为 V0.5：删除“匿名入室/临时 userId/昵称唯一即身份”，改为注册/登录/账号模型。
- `2.1.3 昵称全局唯一` 保留，但改为“用户名唯一不可改 + 昵称唯一可改（3 次）”。
- `6.7/7.4/9.3 永久存档` 改为“在线 1 年 + 可导出”；审计日志 3 年单独定义。
- `8.5 管理员操作不可删除` 需明确为审计日志留存期内不可删除。
- 新增账号/命名/留存相关表、接口、限流、验证码、隐私同意、导出/注销入口。
- 对局导出/回放必须在服务端做时点鉴权，不能只隐藏前端按钮。

## 验收要点

1. 12 位用户名注册成功，13 位被拒绝。
2. 昵称边界：12 个英文字母成功；6 个汉字成功；7 个汉字被拒绝；3 个汉字 + 6 个 ASCII（宽度 12）成功；3 个汉字 + 7 个 ASCII（宽度 13）被拒绝；1 个字符被拒绝（至少 2 个字符）。
3. `admin`、`Admin`、`Ａdmin` 均被保留名拦截。
4. `Alice` 与 `alice` 不能同时注册；昵称同理；全角/半角视为重复。
5. 第 1–3 次改名成功，第 4 次返回 `NICKNAME_CHANGE_LIMIT`。
6. 改名失败不增加次数；24h 冷却生效。
7. 旧昵称 30 天内不能被其他账号使用；本人可改回但消耗一次。
8. 对局中改名返回 `NICKNAME_LOCKED_IN_SESSION`。
9. 两个并发注册同一昵称，只有一个成功，另一个 409。
10. 管理员强制改名不计入用户 3 次，且写审计。
11. 未完成的多桌同牌不能导出/回放；对局中不能看到另一桌结果。

## 未决/后续

- 邮箱验证与自助找回（需 SMTP）。
- 管理员多账号/权限细分（当前单 `admin` 过渡）。
- 昵称唯一带来的“抢名/占名”运营策略；必要时管理员重置改名次数。
- 公网隐私政策、注册同意、数据出境等合规文本。
- 用户名/昵称同形异义字符（homoglyph）检测，可作为后续加固。
