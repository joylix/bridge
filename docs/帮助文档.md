# 帮助文档

本文件说明游戏中的“计点/贴点制”与“叫牌、打牌规则浏览与修改”功能。

---

## 一、计点与贴点制

### 1. 标准计点（IMP）

每一副牌先按标准复式计分得到分数差（南北分 − 东西分），再按 WBF 标准表换算为
带符号的 **IMP（点数）**：正数表示南北赢，负数表示东西赢。

### 2. 贴点制

“贴点制”在标准 IMP 基础上，再按双方大牌点（HCP，A=4 / K=3 / Q=2 / J=1，全副 40 点）
做公平性修正。启用后，本副最终点数为：

```
本副点数 = IMP −（胜方联手大牌点 − 20）
```

- **胜方**：本副得分方——定约方成约时为定约方，宕墩时为防守方。
- 因为全副共 40 点，`胜方大牌点 − 20` 等于**双方大牌点差的一半**。
- 结果**可以为负**：拿高牌的一方若只赢到很少的 IMP，会被倒扣，从而鼓励低点进局、进贯。
- **流局（四家 Pass）**：没有得分方，改由大牌点多的一方贴点给少的一方，
  即 `本副点数 = 20 − 南北大牌点`。大牌点多的一方计负、少的一方计正；双方各 20 点记 0。

示例：

| 情况 | 分数 | IMP | 双方大牌点 | 贴点 | 本副点数 |
|------|------|-----|------------|------|----------|
| 南北 26 点做成 3NT | NS +400 | NS +9 | 26 : 14 | 6 | NS +3 |
| 南北 34 点仅成局 | NS +420 | NS +9 | 34 : 6 | 14 | NS −5（东西 +5） |
| 东西 12 点赢 3 IMP | EW +100 | EW +3 | 28 : 12 | −8 | EW +11 |
| 四家 Pass（流局） | 0 : 0 | 0 | 26 : 14 | 6 | NS −6（东西 +6） |

### 3. 循环与胜负

逐副折算后的点数按循环长度（默认 8 副，可切换 16 副）累加：

- **NS 累计点数 / EW 累计点数**：本循环内双方各自净得点数；
- **总点数差（计点胜负）**：`NS 累计 − EW 累计`，即当前循环的胜负。

计分面板（右侧“计点”区域）默认开启“贴点制”，并展示：

- 本局双方大牌点；
- 本局原始 IMP（未贴点）；
- 贴点调整量；
- 贴点后的本局点数、累计点数与总点数差。

取消勾选“贴点制”即可切换为纯 IMP 统计。贴点所需的双方大牌点会随对局一起归档，
因此切换开关后，历史对局与累计点数会立即按新口径重算。

## 二、叫牌规则与打牌规则的浏览、修改

### 1. 入口

点击页面顶部工具栏的 **“规则管理”** 按钮，打开“叫牌 / 打牌规则”窗口。

### 2. 两个页签

- **叫牌规则**：对应 `src/rules/bidding/*.yml`（默认 `precision`，备选 `natural`）。
- **打牌规则（首攻）**：对应 `src/rules/play/leads*.yml`，由 YAML 规则驱动。
- 跟牌 / 垫牌的防守信号为程序内启发式（见下文“打牌约定细则”），
  约定文档位于 `src/rules/play/signals.yml`。

### 3. 打牌约定细则

当前版本实现以下防守约定：

| 场景 | 约定 |
|------|------|
| 第二家跟牌 | 通常出小牌；对手领出 10 以上的荣誉大牌时，用**最小能盖过它的牌**盖打；同伴领出的荣誉大牌不盖 |
| 第三家跟牌 | 同伴的荣誉大牌已赢则出小牌；同伴的小牌当前虽赢但可能被第四家超过时，出**最小能赢的牌**保护；对手当前赢时同样用最小赢张（连张时保留更大牌） |
| 第四家跟牌 | 能赢则用**最小赢张**；同伴（第二家）已经赢墩时不得无谓超打同伴 |
| 跟牌（张数信号） | 该花色剩**偶数张**时“先大后小”，剩**奇数张**时“先小后大”；信号张只用 10 及以下，保留 J 以上大牌 |
| 对方 NT 定约 · 首攻（仅防守方） | 手中**没有长套**（四门均 ≤4 张）时，首攻**敌方未叫过的高级花色**（长四）；有 5+ 张长套时首攻长套。默认取**第 4 张**；若长套顶张为 AKQ/KQJ/QJT/JT9 等连张，则改出**连张顶张** |
| 垫牌 · 无将 | 从**不鼓励（荣誉力量最弱）**的花色垫最小牌。若已知同伴长套，优先避开；只能垫该花色时**保留低牌、改垫最小荣誉牌**，避免堵塞桥引 |
| 垫牌 · 有将（无损失鼓励） | 若某非将花色有力量且存在无损失的高信号张（8/9/10），垫该张表示**鼓励同伴攻此花色**；不从同伴长套垫。没有则回退为“最弱花色垫最小牌” |

同伴长套的判定：明手可见时，读取明手 5+ 张且有荣誉的花色；否则参考同伴在叫牌中叫过的花色（1♣/1♦ 在精确制中可能是短套或虚叫，不单独作为长套）。

### 4. 浏览细则

- 在文件下拉框中选择要查看的规则文件；
- “浏览细则”以表格展示每条规则的：
  - 叫牌：`id`、说明、`sequence`（相对座位序列）、`when`（手牌条件）、`action`（叫品）、`priority`；
  - 首攻：`id`、说明、`contract_type`（NT / 有将）、`role`（适用方：防守方 / 庄家侧 / 不限）、`when`、`lead`（首攻策略）、`priority`。
- 表格按 `priority` 从高到低排列，与 AI 的裁决顺序一致。
- 叫牌条件中的 `openingSeat` 表示开叫座位：`1`=发牌人，`2`=第二家，`3`=第三家，`4`=第四家；
  仅用于首叫（开叫）规则。

### 5. 修改细则

1. 点击“编辑源码”，进入 YAML 编辑模式；
2. 修改规则文本（可改条件、动作、优先级，也可新增/删除规则）；
3. 点击“保存并应用”：
   - 先做语法与基本字段校验，失败时展示具体错误，不会写入；
   - 校验通过后保存到浏览器本地（`localStorage`），并立即应用到 AI；
4. 点击“恢复默认”可清除本地修改，回到内置 YAML。

若当前浏览的文件不是 AI 正在使用的文件，可点击 **“设为当前使用”** 切换激活文件。
规则修改保存在本机浏览器中，刷新页面后仍然有效；不同浏览器/设备之间不共享。

> 提示：修改 `action` / `lead` 时请使用规则文件中已有的取值，或确认程序支持的新取值，
> 否则该条规则可能无法产生预期动作。

### 6. 权限说明

- **当前阶段**：所有用户都可以浏览并修改规则（编辑、保存、恢复默认均可用）。
- **后续阶段**：接入账号/后台后，将改为**仅系统管理员可修改**，普通用户只读。
  权限策略集中在 `src/permissions.ts` 的 `RULES_ADMIN_ONLY` 开关：
  - `false`（当前）：所有用户可编辑；
  - `true`：仅 `admin` 角色可编辑，普通用户打开规则窗口时只读。
