## 0 术语、数据分层与规范分层

### 0.1 术语

| 术语 | 英文 | 定义 |
|---|---|---|
| 大厅 | Lobby | 玩家登录后的主入口，含在线名单、牌室列表、聊天、管理员入口 |
| 牌室 | Room | 室主建立的虚拟空间，含名称、房间性质、玩法、总副数等配置 |
| 盘 | Session | 一次连续对局单元（一次"开始"到"结束"），一盘含若干副 |
| 副 | Board（UI 文案） | 桥牌的一副牌；数据模型拆为 `Deal` + `TableBoard` |
| 牌型 | Deal | 同一副牌的定义：牌号、四手牌、发牌人、局况；一盘内唯一，可分发到多桌 |
| 桌副 | TableBoard | 某一桌对某个 `Deal` 的叫牌、出牌、定约、结果与原始分；每桌一份 |
| 盘副聚合 | SessionBoard | 对同一 `Deal` 的各 `TableBoard` 做跨桌聚合（队分、IMP、调整分）；派生数据，可重算 |
| 桌 | Table | 实际打牌的 4 席位单元；队式赛可有多桌 |
| 席位 | Seat | 桌内的北/南/东/西（或队式赛对应方位） |
| 阵营 | Camp | 队式赛的红方/蓝方等候区，非队式赛不需要 |
| 账号 | Account | 稳定身份，含邮箱、用户名、昵称、密码哈希、角色与状态；`userId` 全局唯一 |
| 用户名 | Username | 登录标识，归一化后全局唯一、不可修改、公开不可见 |
| 昵称 | Nickname | 公开显示名，归一化后全局唯一、可修改且终身最多 3 次 |
| 玩家 | Player | 注册账号登录后的真人 |
| 管理员/裁判 | Admin / Director | 系统管理员账号，承担裁判职能（过渡方案） |
| 房间性质 | `roomNature` | `practice / casual / competitive`，创建时固化，**权限判断依据之一** |
| 盘状态 | `sessionStatus` | `preparing / starting / playing / paused / completed / aborted`，**生命周期状态** |
| 成绩资格 | `scoringEligibility` | `eligible / ineligible / pending`，**本盘是否进入正式成绩**，独立于 `roomNature` |
| 桌副状态 | `boardStatus` | `IN_PROGRESS / PLAYED / PASSED_OUT / CANCELLED / ADJUSTED / INCOMPLETE` |
| 叫牌体系 | `biddingSystem` | 搭档间约定的叫牌含义集合，按 pair 挂载，Session 内锁定 |
| 声明体系 | `declaredSystem` | 用户声称采用的体系（`systemId / version / source`） |
| 实际执行体系 | `effectiveSystem` | AI 实际使用的规则集（`rulesetId / systemId`）；真人搭档时无 AI 执行则为 `null` |
| 解释来源 | `explanationSource` | 叫品解释来自 `builtin / uploaded-text / system-inferred`，区分确定性与用户原文 |
| 聊天层 | `chatLayer` | `LOBBY / ROOM / TABLE / WHISPER` |
| 快捷短语卡 | `chatCard` | 预置固定短语，正式比赛牌桌唯一可用聊天形式 |

**数据模型分层**：`Account → Lobby → Room → Session → Deal → TableBoard`，并由同一 `Deal` 的各 `TableBoard` 派生 `SessionBoard`；`Seat` 挂在桌位配置与 `TableBoard` 上。`Account` 是全局身份，所有对局、成绩单、回放、权限和审计均挂到稳定 `userId`。单桌与多桌队式赛共用同一套结构。计分策略（合约分/队式 IMP）插件化；MP/VP 仅保留字段，V1 不启用。**四个维度不得共用一个标志**：`roomNature`（房间业务性质）、`sessionStatus`（生命周期）、`scoringEligibility`（成绩资格）、`boardStatus`（桌副状态）分别存储、分别授权、分别快照。

### 0.2 规范分层与配套文件声明

> **规范分层原则**：SRS 冻结"业务语义与约束"；完整规则条文引用 WBF 规则与《桥牌规则与数据交换规范 v2》；并发机制、幂等键、快照频率等实现机制见 `docs/adr/`（ADR-0004~0007）；性能测试条件与采样方法见测试计划。
>
> - **SRS（本文档）**：业务语义、状态转移、结算规则、权限矩阵、验收条件。
> - **ADR-0004~0007**：房间性质与授权、队式赛结算、并发与事务、实时权限投影的实现机制。
> - **《桥牌规则与数据交换规范 v2》**：JSON/PBN/CSV 交换契约、事件信封、受众投影、损失报告。
> - **测试计划**：性能采样、DDS 降级阈值、并发规模、测试硬件、安全渗透测试。
> - **WBF 规则**：完整叫牌/出牌/计分条文（引用，不在本文重写）。
>
> **配套文件状态声明**：ADR-0004~0007、《桥牌规则与数据交换规范 v2》、测试计划均为配套依据，**尚未经本 SRS 评审专项确认其与 SRS 完全一致**；本 SRS 评审仅确认 SRS 自身的完整性与内部一致性。配套文件须各自完成专项评审，评审通过后方可支撑第 12 章交付门槛。

### 0.3 叫牌体系术语与三层分离

| 术语 | 定义 |
|---|---|
| `declaredSystem` | pair 在 Session 开局前声明的体系标识，含 `systemId / version / rulesetId / source（builtin|uploaded） / declaredBy / declaredAt` |
| `effectiveSystem` | AI 实际执行的体系；人类 + AI 且人类声明内置体系时等于 `declaredSystem`；人类声明上传/未编译时回退内置精确制并记录 `fallbackToDefault=true`；双 AI 为系统默认；真人 + 真人时为 `null`（无 AI 执行） |
| `explanationSource` | 叫品解释来源：`builtin`（系统内置体系规则生成，确定性）、`uploaded-text`（用户上传原文，标注"用户提供，未经系统验证"）、`system-inferred`（系统推断，标注"系统推断，仅供参考"） |
| `rulesetId` | 规范化 IR 的 SHA-256，见交换规范 v2 §4.11 |

**分层原则**：
1. **pair 级**：叫牌体系按 pair 声明，不是全桌统一规则；每 pair 独立，互不覆盖。
2. **声明时点**：Session 开局前锁定；`practice` 房允许逐副声明，但不计入正式成绩（`scoringEligibility=ineligible`）。
3. **解释与执行分离**：上传体系 V1 只解释不执行；AI 只执行内置已编译体系。
4. **三层可追溯**：`declaredSystem / effectiveSystem / explanationSource` 三者分别记录，进入事件流、成绩单与导出；AI 回退默认时必须在披露面板明示"实际执行体系"。

## 1 概述

### 1.1 产品目标
实现线上桥牌对局系统：玩家注册账号并登录后进入大厅，在大厅查看在线名单与公开牌室列表、进入牌室；室主命名牌室、定义房间性质、玩法与总副数；支持单桌 4 人玩法与红蓝阵营队式赛；选手可自行落座或由室主拖拽分配，举手准备；室主判断后手动开局，空位按组队需要自动补 AI；叫牌/出牌超时自动判 Pass 或降智 AI 托管；系统管理员（裁判）可对比赛进程进行干预；自动计分、对局记录与回放在线保存 **1 年**并可导出；队式赛提供转播观战；支持 pair 级叫牌体系声明与解释、分层聊天与快捷短语。

### 1.2 范围
- **包含**：注册/登录/个人资料、会话与多设备、大厅、牌室创建与配置（含 `roomNature`）、单桌玩法、队式赛（红蓝阵营、结对、多桌同牌、跨桌 IMP）、等候区与座位管理、举手准备、手动开局与 AI 补位、叫牌/出牌超时与托管、合约分/队式 IMP 计分、管理员干预、呼叫管理员、转播观战、对局日志与回放、旁观、室主权限移交、最近对局记录、成绩单与 JSON/PBN/CSV 导出、pair 级叫牌体系声明与解释披露、四层聊天与快捷短语卡、**成绩资格判定**。
- **不包含**：付费会员体系（演示期前 50 副试用，见 9.6）、MP/VP 赛制与双人赛多轮编排（V1 只保留字段）、音视频、移动端适配、瑞士移位、梯级挑战赛、导入预发固定牌型（预留接口）、独立裁判账号体系（以系统管理员代行）、邮箱验证与邮件自助找回（V1 由管理员重置，见 2.1.5）、**上传体系驱动 AI 执行**（V1 仅解释，执行单独立项，见 6.10.4）、**跨设备演示权益**。

### 1.3 设计原则
1. **数据模型与接口一次做对**：实体、主键、状态机、协议和权限矩阵一次冻结；未决项写 ADR。
2. **真人优先、AI 兜底**：任何席位缺失都能由 AI 补齐。
3. **原子开局**：开局一次性完成"移出未举手者→补 AI→校验→锁定→发牌"。
4. **副中锁定、副间可调**。
5. **管理可干预、操作可追溯**。
6. **授权依据持久化**：房间性质、角色、成绩资格、导出时点等一律以服务端持久化数据为准。
7. **解释与执行分离**：解释性信息与可执行逻辑分离。
8. **四维分离**：`roomNature / sessionStatus / scoringEligibility / boardStatus` 不得共用一个标志。

## 2 玩家账号、大厅与管理角色

### 2.1 注册、登录与命名

> 本节取代 V0.4 的"昵称入室/匿名临时 userId"模型。

#### 2.1.1 注册与登录
1. 注册必填：**邮箱、用户名、昵称、密码**。
2. 邮箱：必填、唯一、规范化为小写、可修改、**V0.7 暂不验证**；预留 `emailVerifiedAt`，未验证前不能用于自助找回。**风险接受**：公网长期运营前必须补邮箱验证，否则账号找回完全依赖管理员，见 10 待确定第 1 项。
3. 登录：**用户名 + 密码**；邮箱不作为登录名。
4. 密码：至少 8 位，禁止与用户名/昵称相同；服务端使用强哈希（Argon2id/bcrypt）存储，不存明文、不写日志。
5. 注册风控：图形验证码 + 每 IP 每小时最多 5 次注册 + 登录失败锁定；内网演示可关闭。
6. 未登录用户只能访问注册/登录页；**旁观与聊天也必须登录**。
7. 忘记密码：V1 仅管理员重置，生成临时密码并强制首次登录修改；不做邮件自助找回。

#### 2.1.2 用户名（登录标识，公开不可见）
1. 长度 **3–12 位**，正则 `^[A-Za-z][A-Za-z0-9_]{2,11}$`。
2. 归一化：`NFKC` + 转小写 + 去首尾空白后查重。
3. 全局唯一；并发注册/改名由服务端唯一约束裁决，冲突返回 `409`。
4. 保留名（大小写不敏感、可配置）：`admin`、`administrator`、`support`、`system`、`root`、`bridge`、`null`、`undefined` 等。
5. 用户不可修改；管理员可纠正明显 typo，必须填写原因并写审计，不改变 `userId`。
6. 只对本人和管理员可见；公开界面只显示昵称。

#### 2.1.3 昵称（公开显示名）
1. 长度：至少 2 个字符、最多 12 个显示宽度。汉字/全角按 2，ASCII 按 1；emoji 不支持。
2. 宽度按 `NFKC` 归一化后计算。
3. 允许中文、英文字母、数字、下划线、连字符、单词间单个空格；不允许首尾空格、连续空格、控制字符、零宽字符、emoji。
4. 归一化：`NFKC` + 去首尾空白 + 折叠连续空格 + 大小写不敏感后查重；**保留显示大小写**。
5. 归一化后**全局唯一**；与用户名两个独立命名空间；都禁用保留名。
6. 昵称经敏感词过滤；管理员可强制改名。

#### 2.1.4 改名规则
1. 终身最多 **3 次**；初始昵称不计次；失败/被拒不计数；管理员强制改名不计入。
2. 冷却：成功改名后 **24 小时**内不可再改；成功后 `nicknameChangeCount + 1`。
3. 对局中禁止改名：`starting / playing / paused` 且已落座时返回 `NICKNAME_LOCKED_IN_SESSION`；大厅、等候区、旁观时可改。
4. 旧昵称保留 **30 天**；本人可改回但消耗一次次数；到期释放；释放与注册并发由 `NameRegistry` 唯一约束裁决，冲突方返回 `NICKNAME_RESERVED`。
5. 日志/回放/成绩单保存**当时昵称快照**；个人资料页显示当前昵称。

#### 2.1.5 会话、账号安全与密码重置
1. 会话 Cookie：`httpOnly + Secure + SameSite=Lax`；默认 7 天，"记住我"30 天；允许多设备登录，但**同一牌室只能占一个座位**。
2. 登录失败锁定（按账号 + IP）、注册限流、昵称可用性查询限流。
3. 管理员引导账号：单个 `admin`，初始密码从环境变量或首次启动生成，不入库明文、不进 Git；首次登录强制改密；公网部署禁止固定简单密码。
4. 角色（`player/admin`）保存在服务端会话/数据库，客户端不可自报；所有管理接口服务端鉴权。
5. 用户名/昵称并发注册、改名只能一个成功，其余 `409` + 明确错误码。
6. **密码重置（P1）**：管理员重置密码须二次确认、填写原因、写审计（操作人、目标 `userId`、时间、IP）；重置后**该账号所有活动会话立即失效**（强制重新登录），临时密码强制首次登录修改；审计日志保留 3 年。
7. **管理员账号恢复（P1）**：单 `admin` 丢失凭据时，通过部署环境变量或离线恢复流程重置；流程须写入运维手册，不得依赖邮件自助。
8. **邮箱验证风险接受**：V1 不验证邮箱，账号找回依赖管理员；公网长期运营前必须补邮箱验证与自助找回（10 待确定第 1 项）。

#### 2.1.6 邮箱修改与并发约束
1. 邮箱修改需验证旧密码 + 新邮箱唯一性校验；成功后写审计（旧邮箱、新邮箱、时间、IP），不改变 `userId`。并发修改由 `Account.email` 唯一约束裁决，冲突 `409`。
2. 邮箱修改与登录、注销操作互斥（同一账号事务串行化）。

#### 2.1.7 账号状态、注销与命名查重
1. 管理员可封号/解封；封号后会话立即失效，座位按掉线规则处理。
2. 用户可申请注销，**30 天冷静期**；冷静期内可撤销；期满后账号资料匿名化/删除，对局数据按 9.6 处理。
3. 连续 2 年未登录先提醒，再按注销策略处理。
4. 账号与命名相关表：

```text
Account
  id, email, emailVerifiedAt?, passwordHash,
  username, usernameNormalized,
  nickname, nicknameNormalized,
  nicknameChangeCount, nicknameChangedAt,
  role, status, createdAt, lastLoginAt

NicknameChange
  accountId, oldNickname, newNickname,
  changedAt, actorType (user|admin), reason
```

5. `NameRegistry`：

```text
NameRegistry
  kind (username|nickname)
  normalized
  ownerAccountId
  status (active|reserved)
  reservedUntil
  UNIQUE(kind, normalized)
```

6. 错误码：
   - `USERNAME_INVALID / USERNAME_TAKEN / USERNAME_RESERVED`
   - `NICKNAME_INVALID / NICKNAME_TAKEN / NICKNAME_RESERVED`
   - `NICKNAME_COOLDOWN / NICKNAME_CHANGE_LIMIT / NICKNAME_LOCKED_IN_SESSION`
   - `EMAIL_TAKEN / EMAIL_MODIFY_CONFLICT`
   - `PASSWORD_RESET_FORBIDDEN`（非管理员或二次确认未完成）

### 2.2 角色与权限
| 角色 | 权限 |
|---|---|
| 系统管理员/裁判 | 响应呼叫、中止某桌某副、踢出选手、警告、扣分/调整分、暂停某桌、查看所有牌室与对局、进入任意牌室（管理态）、重置密码、封号/解封；争议处理时可查看暗手，但必须留痕 |
| 室主 | 命名/配置牌室（含 `roomNature`）、分配阵营、拖拽上座/拽起、开始对局、副间换人换 AI、设置 AI 难度、踢人、解散牌室、**仅练习房（`practice`）修改分数（留日志）**、移交室主 |
| 玩家（已登录） | 入室、自落座/离座、举手/取消举手、呼叫管理员、退出牌室、聊天（分层）、查看本人最近对局与导出本人参与的对局 |
| 旁观者（已登录） | 进入观战席、切换观战桌、看明手与叫牌出牌记录，**不可见四家手牌**、不可参与叫牌出牌 |

> **权限边界（P1）**：敏感操作（改分、踢人、暂停桌、查看暗手、重置密码、封号）须**二次确认**（弹窗显示目标、前后值、原因输入）；管理员与室主权限分离，室主不得执行管理员专属操作；误操作恢复规则见 6.8.3；争议复核见 6.8.4。改分授权以持久化 `roomNature` 为准。

### 2.3 室主权限移交
1. 室主退出或掉线超时，权限移交给**在线真人中最早入室者**；掉线者不参与排序。
2. 无可移交真人时：**当前盘继续打完（含全 AI）**；盘结束后牌室"冻结"：不能开局、不能开新盘；冻结后 30 分钟无真人则销毁。
3. 移交事件写入牌室日志。

### 2.4 大厅功能
1. **在线玩家名单**：昵称、状态（大厅中/在牌室/对局中/旁观中）、所在牌室名称；支持按昵称搜索。
2. **在线人数统计**：按玩法分类。
3. **公开牌室列表**：名称、玩法、房间性质、人数/上限、状态；点击进入等候区。
4. **私人牌室**：不展示，凭邀请码/链接（可设密码）进入。
5. **大厅聊天区**：`audience=LOBBY`，全体在线可见；敏感词过滤；限频见 2.6；持久化 90 天。
6. **管理员入口**：管理面板（6.8）。
7. **最近对局记录**：按 `userId` 查询；对局中不展示未完成牌结果；`scoringEligibility=ineligible` 单独标注。

### 2.5 呼叫管理员
1. 牌室与对局界面设【呼叫裁判】按钮。
2. 推送通知含牌室名、桌号、呼叫者昵称、事由（可选）。
3. 当前桌显示"已呼叫裁判"；管理员响应后以旁观者+管理权限进入。
4. 无在线管理员时提示；呼叫记录写日志。

### 2.6 聊天分层、快捷短语、限频与禁言

#### 2.6.1 四层聊天与受众

| 层 | `audience` | 可见范围 | 持久化 | 自由聊天 | 备注 |
|---|---|---|---|---|---|
| 大厅聊天 | `LOBBY` | 全体在线登录用户 | 90 天 | 允许 | 2.4.5 |
| 牌室聊天 | `ROOM` | 该牌室内成员（含本室旁观者），不含外部 | 90 天 | 允许（含快捷短语） | 3.4 |
| 牌桌聊天 | `TABLE` | 本桌 4 席 + 本桌裁判；**不推旁观/转播** | 90 天 | **正式比赛禁止，仅快捷短语卡** | 2.6.5；旁观/转播用独立频道 |
| 悄悄话 | `WHISPER:<userId>` | 两名人类之间；机器人不可为对象 | 90 天 | 允许（受禁言约束） | 2.6.6 |

- 四层均须登录。
- 牌桌自由聊天可用性由 `roomNature` 与 `sessionStatus` 决定（2.6.5）。
- 旁观/转播频道独立（6.6），不与 `TABLE` 混流；转播延迟释放（6.7.4）。

#### 2.6.2 限频

1. **维度**：`userId` 主维度，IP 辅助；多设备共享 `userId` 配额；同 IP 多账号合并 IP 配额。
2. **默认配额**（管理员可配，9.5）：

| 层 | 每小时 | 每天 |
|---|---|---|
| 大厅 `LOBBY` | 20 | 100 |
| 牌室 `ROOM` | 60 | — |
| 牌桌 `TABLE` | 120 | — |
| 悄悄话 `WHISPER` | 30/小时/对象 | — |

3. **超限**：返回 `CHAT_RATE_LIMITED`（含冷却秒数），不静默丢弃；写风控日志；连续超限可临时禁言（管理员可配）。
4. **滑动窗口**：服务端权威；客户端倒计时仅提示。

#### 2.6.3 快捷短语卡（聊天卡）

1. **定位**：预置固定短语，正式比赛牌桌唯一可用聊天形式；牌室也可用。
2. **默认短语集**（管理员可增删）：礼节类（打招呼、问好、Good play、Sorry、谢谢、再见）；节奏类（请快些出牌、请稍等、我需要一点时间）；替补类（邀请某旁观者替代断线/有事离开用户，2.6.4）；裁判类（呼叫裁判）。
3. **语言**：预置本地化文本（中英双语可切换），无自由文本输入；仅存短语 ID + 系统生成参数。
4. **限频**：计入牌桌配额；礼节类可放宽（管理员可配独立配额），不得绕过总配额。
5. **禁止**：不得携带自由文本参数（替补目标由系统生成）。

#### 2.6.4 邀请旁观者替补

1. **场景**：本桌真人断线或离开，室主/裁判邀请本室旁观者替补。
2. **发起**：室主/裁判点击"邀请旁观者替补" → 系统按以下**选择顺序**自动选目标（P1）：
   - 优先：本室旁观者中当前在线、未被其他桌邀请、未处于 `WHISPER` 禁言冲突者；
   - 排序：入室时间早者优先；同时间按 `userId` 字典序（确定性）；
   - 排除：已被本桌邀请但未响应者、同一旁观者已被其他桌"邀请中"者。
3. **互斥与原子性（P1）**：同一旁观者同一时刻只能有一个"邀请中"状态（`UNIQUE(targetUserId)` 于 `SubstituteInvite WHERE status=PENDING`）；邀请、席位锁定、AI 退出在同一事务内完成；并发邀请同一目标时仅一个成功，其余返回 `SUBSTITUTE_INVITE_CONFLICT`。
4. **接受/拒绝/超时**：接受后按 6.5 接管；拒绝或 30 秒未响应邀请失效；失效后释放互斥。
5. **审计**：邀请、接受、拒绝、超时写牌室日志与事件流；正式比赛替补不改变已打副原始分。
6. **快捷短语**：也可通过"邀请替补"卡触发，目标由系统按上述规则选，不由用户输入。

#### 2.6.5 正式比赛牌桌聊天限制

1. **触发条件**：`roomNature = competitive` 且 `sessionStatus ∈ {starting, playing, paused}`。
2. **限制**：`TABLE` 层禁用自由聊天，仅快捷短语卡；旁观/转播频道不受限（但受 6.6 隔离与 6.7.4 延迟）。
3. **解除**：`sessionStatus = completed` 后恢复。
4. **违规**：返回 `TABLE_CHAT_CARD_ONLY`；服务端拒绝并记日志；反复尝试可被裁判警告/处罚。
5. **`practice` / `casual`**：牌桌自由聊天允许（`practice` 室主可关），受敏感词与裁判审计约束。

#### 2.6.6 悄悄话与比赛禁言

1. **对象**：仅两名人类；机器人不可为对象；不得对同桌对手发悄悄话。
2. **禁言条件**：发送者或接收者 `已落座 && sessionStatus ∈ {starting, playing, paused}` 时返回 `WHISPER_LOCKED_IN_SESSION`。
3. **允许场景**：大厅、等候区、旁观、`practice` 房非对局时段。
4. **审计**：不进入普通对局导出，写聊天留存 90 天，裁判可查。

#### 2.6.7 错误码
- `CHAT_RATE_LIMITED / WHISPER_LOCKED_IN_SESSION / WHISPER_TARGET_INVALID / CHAT_AUDIENCE_FORBIDDEN / TABLE_CHAT_CARD_ONLY / CHAT_CARD_INVALID / SUBSTITUTE_INVITE_INVALID / SUBSTITUTE_INVITE_CONFLICT`。

## 3 牌室设计

### 3.1 牌室创建与配置（含房间性质）
室主创建牌室时设定：
- **牌室名称**（必填）、对局备注（可选）；
- **房间性质 `roomNature`**（必填，创建时固化，Session 内不可切换）：
  - `practice`：练习房。允许室主改分；**默认 `scoringEligibility=ineligible`**（见 3.5）；导出标 `practice=true`；队式 IMP 仅参考；允许逐副声明体系；牌桌自由聊天可关。
  - `casual`：休闲房。室主不可改分；**默认 `scoringEligibility=ineligible`**（计入个人记录但不计正式排名）；牌桌自由聊天允许。
  - `competitive`：正式房/队式赛。仅管理员可改分；**`scoringEligibility` 按 3.5 判定**；牌桌 Session 进行中仅快捷短语卡。
- **玩法类型**：`单桌4人标准桥牌` / `队式赛（红蓝阵营，支持多桌）`；
- **总副数**：自定义或"不限副数，手动结束"；
- **最低真人数**（5.1）；
- **计分模式**：合约分必选；队式赛 IMP 必选；MP/VP 预留不启用；
- **AI 难度**：简易/普通/高手，可全局或按座位；
- **断线接管策略**：`超时自动 AI 接管` / `保留座位等待室主决定`（默认前者）；
- **旁观/转播开关**；**房间密码**；**聊天开关**；等候区上限。

**四维分离**：`roomNature` 是权限判断依据之一，但**不单独决定成绩资格**；成绩资格由 `scoringEligibility` 独立判定（3.5）。服务端以持久化 `roomNature` 作为改分、导出标注、牌桌聊天限制的依据；以 `scoringEligibility` 作为排名、正式成绩、导出的依据。`roomNature` 与初始 `scoringEligibility` 写入 `Session` 快照，Session 内 `roomNature` 不可改，`scoringEligibility` 仅按 3.5 规则在定义时点变更。

合法组合：

| roomNature | 玩法 | 改分权限 | 初始 scoringEligibility | 导出标注 | 牌桌聊天（进行中） |
|---|---|---|---|---|---|
| practice | 单桌/队式 | 室主 + 管理员 | ineligible | `practice=true` | 自由（可关） |
| casual | 单桌/队式 | 仅管理员 | ineligible | `practice=false, eligible=false` | 自由 |
| competitive | 单桌/队式 | 仅管理员 | 按 3.5 判定 | `practice=false, eligible=<值>` | 仅快捷短语卡 |

### 3.2 牌室加入
公开牌室空位可直接进入等候区；私人牌室凭邀请码/密码。等候区上限默认 20（室主可调）。

### 3.3 牌室状态流转
```
登录进入大厅 → 创建或进入牌室 → 落座/拖拽分配 → 举手准备
  → 室主点击【开始】（原子：移出未举手者→补AI→校验→锁定体系→锁定座位→发牌）
  → 对局进行中（逐副：叫牌→出牌→结算） → 副间可调整座位/换AI
  → 达到总副数或室主结束 → 生成成绩单与回放 → 可开下一盘 / 解散牌室
```

### 3.4 牌室界面布局
**A. 等候/准备界面**：等候区 + 座位面板（标注真人/AI/空位）；队式赛红蓝阵营 + 结对；自落座/拖拽/拽起；举手；房间设置（显示 `roomNature` 不可改）；**叫牌体系声明面板**；聊天框（含快捷短语）；【呼叫裁判】；【开始准备】；【开始】前弹确认（真人/AI 分布、最低真人数、各 pair 体系声明摘要、预期 `scoringEligibility`）。

**B. 对局界面**：四方位手牌、叫牌区、出牌区、明手；完整叫品 + 【提醒】（按叫牌方体系生成）；实时计分 + 跨桌比对；超时倒计时；【呼叫裁判】；**对手体系披露面板**（显示 `declaredSystem / effectiveSystem / explanationSource`）；**牌桌聊天区**（`competitive` 进行中仅快捷短语卡）；队式赛转播入口。

### 3.5 牌室生命周期与成绩资格判定

1. 牌室持续存在，直到室主解散 / 无真人且当前盘结束后超时（默认 30 分钟）销毁。
2. 对局中 4 席位齐全即可推进；全 AI 对局由服务端驱动。
3. **成绩资格 `scoringEligibility` 判定（P0-1 修订）**：
   - **初始值**：`practice`/`casual` 为 `ineligible`；`competitive` 为 `pending`。
   - **判定时点**：`competitive` 房间在 `Session` 结束（`completed`）时最终判定；判定依据为**整盘内是否有至少一名真人完成过至少一次有效动作**（有效动作 = 一次合法叫牌或一次合法出牌，且该动作发生在真人控制的座位上，非 AI 托管、非超时自动 Pass）。
   - **中途变化**：开局后真人退出或转为全 AI，不立即改变资格；最终判定以整盘累计为准。若整盘无任何真人有效动作，则 `ineligible`；否则 `eligible`。
   - **追溯**：`scoringEligibility` 改变（仅 `pending → eligible/ineligible` 一次）不追溯已完成的副，但成绩单与排名按最终值整体计入或排除；快照记录判定时点与依据事件。
   - **审计**：判定结果、依据事件、判定时点写入 `Session.scoringEligibilitySnapshot` 与审计日志；导出与成绩单携带该字段。
4. `roomNature` 进入 Session 快照后，该盘内改分、导出、排名、IMP 计入、牌桌聊天限制按快照执行；`scoringEligibility` 独立按 3.5.3 判定。
5. 全 AI 对局默认 `ineligible`；练习盘在最近对局中单独标注。

## 4 组队与座位机制

### 4.1 单桌 4 人玩法
1. 固定 4 席位：北/南/东/西；南北一队、东西一队；副内搭档固定。
2. 选手自落座或室主拖拽；室主可拽起重排。
3. 空位开局时由 AI 成对补位（4.4）。
4. 换人/换 AI 仅副间，副中锁定；换人不重置队伍累计分。

### 4.2 队式赛玩法（红蓝阵营，多桌）
1. 红/蓝阵营等候区；每方席位需求 = 2 × 桌数。
2. 阵营内结对；上座按固定对位表分配。
3. **固定对位表**（开赛固化，写入 `Session.teamTableMapping`）：

| 桌号 | NS 归属 | EW 归属 |
|---|---|---|
| 1 | 红队 | 蓝队 |
| 2 | 蓝队 | 红队 |
| 3 | 红队 | 蓝队 |
| 4 | 蓝队 | 红队 |
| … | 奇偶交替 | 奇偶交替 |

4. **同牌分发**：各桌 `Deal` 相同、`TableBoard` 各自一份。
5. **原始分符号约定**：每桌 `TableBoard.rawScore.nsRaw = ns − ew`（NS 视角带符号）。红队视角原始分：
   - 红队坐 NS：`+nsRaw`；
   - 红队坐 EW：`−nsRaw`；
   - `redTeamRaw = Σ(红队各桌红队视角原始分)`（**已是代数和，含正负**）。
6. **IMP 换算（P0 公式修正）**：`teamImp = impTable(redTeamRaw)`，**不得**再减 `blueTeamRaw`（`blueTeamRaw` 仅为展示用，`blueTeamRaw = −redTeamRaw`，不得参与换算）。换算表版本 `wbf-2017`，写入 `SessionBoard.impTableVersion`。逐副换算、逐副累加为全盘 teamImp；不得用全盘累计分差一次性换算。
7. **异常结算**：见 6.11 统一异常结算表。
8. 队式赛至少 2 桌；单桌队式退化为普通对局。
9. **附录 C** 为表驱动测试（输入 `redTeamRaw`，输出以随包 `wbf-2017.json` 为准）。

### 4.3 举手与超时离座
1. 落座后真人【举手】，可取消。
2. **举手超时**：从【开始准备】起算，默认 60s；超时自动离座回等候区；室主可关闭自动离座。
3. 拽起已举手者，准备态重置。
4. AI 落座即视为已准备。

### 4.4 AI 补位规则
1. **成对补位优先**。
2. **单空位**：补 1 AI 与该方真人搭档，标注"AI 搭档"。
3. AI 难度按全局或座位。
4. 补位在开局原子操作中完成，补位后再次校验最低真人数。

## 5 开局规则、并发约束与状态机

### 5.1 室主手动判断开局
由室主点击【开始】；系统仅提供最低真人数硬门槛（单桌默认 ≥2；队式赛每方 ≥1；可配）；不满足时【开始】置灰并提示。

### 5.2 开局原子操作
点击【开始】后服务端一个事务内完成：①移出未举手真人；②按 4.4 补 AI；③校验最低真人数；④**锁定 `systemDeclarations`（6.10.1）**；⑤锁定座位；⑥发牌（队式赛分发同一副到各桌）；⑦初始化 `sessionStatus=starting`、`scoringEligibility=pending`（competitive）或 `ineligible`（practice/casual）；⑧广播开局。任一步失败整体回滚。`start` 命令带 `commandId` 幂等。

### 5.3 并发一致性约束（SRS 层，机制见 ADR-0006）

1. **唯一性约束**：
   - `UNIQUE(sessionId, dealId, tableId)` 于 `TableBoard`；
   - `UNIQUE(sessionId, dealId)` 于 `SessionBoard`；
   - `UNIQUE(streamId, seq)`、`UNIQUE(eventId)` 于事件流；
   - `UNIQUE(sessionId, pairId)` 于 `Session.systemDeclarations`；
   - `UNIQUE(targetUserId) WHERE status=PENDING` 于 `SubstituteInvite`。
2. **事务边界**：开局、发牌、重发、结算明确事务边界；跨桌发牌/结算作为整体或补偿事务。
3. **幂等**：`start` 带 `commandId`；重复提交返回同一结果；重复事件按 `eventId` 去重，重复 `seq` 拒绝。
4. **全桌重发失败**：整体回滚至重发前；不可回滚时进入 `REDEAL_PENDING` 并禁止结算，管理员裁决，写审计。
5. **服务重启恢复**：`seq` 单调、`eventId` 全局唯一；按 `lastSeq` + 快照恢复（含全 AI 对局）。
6. **重算可复现**：`SessionBoard` 重算快照含 `rulesetId / scoringProfile / impTableVersion / tableBoards[].rawScoreVersion / systemDeclarations / effectiveSystems`。
7. **并发裁判操作（P0-4）**：同一 `TableBoard` 的裁判操作（取消/调整/重发）须串行化（行锁或乐观版本号）；重复调整分时后一次覆盖前一次但保留全部历史（`adjustHistory` 数组）；已 `CANCELLED` 的副默认不允许再调整（须先 `REOPEN`，见 6.11）；并发操作冲突返回 `DIRECTOR_OP_CONFLICT`。
8. **事件写入顺序（P0-4）**：状态变更先写事件、后改快照，或同事务内写事件+快照；事件 `seq` 与快照 `lastSeq` 一致；重发时旧事件标记 `supersededBy` 保留，不删除；可重放事件限定为未 `supersededBy` 的事件。

### 5.4 总副数与结束
达到总副数或室主手动结束后，`sessionStatus=completed`，触发 `scoringEligibility` 最终判定（competitive，3.5.3），生成成绩单与回放。

### 5.5 四层状态转换表（P0-4 新增）

**`sessionStatus`（Session 生命周期）**

| 当前 | 允许迁移 | 触发 |
|---|---|---|
| preparing | starting / aborted | 室主【开始】/ 室主取消 |
| starting | playing / aborted | 开局事务完成 / 事务失败回滚 |
| playing | paused / completed / aborted | 裁判暂停 / 达总副数或室主结束 / 异常终止 |
| paused | playing / completed / aborted | 裁判恢复 / 结束 / 终止 |
| completed | —（终态） | — |
| aborted | —（终态） | — |

**`scoringEligibility`（成绩资格）**

| 当前 | 允许迁移 | 触发 |
|---|---|---|
| pending | eligible / ineligible | Session `completed` 时按 3.5.3 判定 |
| eligible | —（终态） | — |
| ineligible | —（终态） | — |

**`TableBoard.status`（桌副状态）**

| 当前 | 允许迁移 | 触发 |
|---|---|---|
| IN_PROGRESS | PLAYED / PASSED_OUT / CANCELLED / INCOMPLETE | 正常结算 / 流局 / 裁判取消 / 超时未完成 |
| PLAYED | ADJUSTED / CANCELLED | 裁判调整分 / 裁判取消 |
| PASSED_OUT | ADJUSTED / CANCELLED | 裁判调整 / 取消 |
| CANCELLED | ADJUSTED / REOPENED | 裁判改判调整分 / 裁判重开（见 6.11） |
| ADJUSTED | ADJUSTED（再次调整，保留历史）/ CANCELLED | 裁判再次调整 / 取消 |
| INCOMPLETE | PLAYED / CANCELLED | 补打完成 / 取消 |
| REOPENED | IN_PROGRESS / CANCELLED | 重新开始该副 / 取消 |

**`SessionBoard.status`（跨桌聚合）**

| 当前 | 允许迁移 | 触发 |
|---|---|---|
| PENDING | COMPLETE / INCOMPLETE / CANCELLED / ADJUSTED | 各桌完成 / 缺桌 / 取消 / 调整后重算 |
| COMPLETE | ADJUSTED / CANCELLED | 调整分 / 取消后重算 |
| INCOMPLETE | COMPLETE / CANCELLED | 补桌完成 / 取消 |
| ADJUSTED | ADJUSTED / CANCELLED | 再次调整 / 取消 |
| CANCELLED | ADJUSTED / REOPENED | 改判 / 重开 |

**`REDEAL_PENDING`**：仅 `Session` 级标记；进入后禁止结算；管理员裁决后迁移至 `playing`（重发成功）或 `aborted`（放弃重发）。

## 6 对局核心功能

### 6.1 发牌与明手
随机洗牌、四家分发；庄家确定后明手自动摊牌；队式赛各桌同副一致。

### 6.2 叫牌、出牌与规则引擎

1. 完整桥牌叫品，叫牌顺序校验，非法叫品拦截。
2. 轮次出牌，出牌合法性校验，自动统计赢墩。
3. 叫牌面板【提醒】按钮：向对手发送简短约定叫说明（仅对手可见，按叫牌方 `effectiveSystem` 生成，`explanationSource` 标注来源，见 6.10.3），内容入日志。
4. 所有叫牌/出牌写入对局日志。
5. **规则版本与状态转移（P0-3 修订）**：
   - **规则版本**：固定采用 **WBF Laws of Duplicate Bridge 2017**（`wbf-laws-2017`），适用范围为叫牌、出牌、定约、赢墩、合约分；本地化差异写入 ADR-0005；版本号写入 `SessionBoard.engine.rulesVersion`。
   - **叫牌状态机**：`AUCTION → (至少一个实质叫品后连续三 Pass) → CONTRACT_SET → PLAY → SETTLEMENT`；四家全 Pass 为 `PASSED_OUT`。
   - **合法性约束（转错误码，SRS 冻结）**：非法叫品 `BID_ILLEGAL`；非法加倍/再加倍 `DOUBLE_ILLEGAL` / `REDOUBLE_ILLEGAL`；非法出牌 `PLAY_ILLEGAL`（跟牌义务、垫牌、首攻限制）；撤回/违规出牌 `PLAY_REVOKE_PENDING`（转裁判裁决，6.2.6）。
   - **定约确定**：实质叫品 + 加倍/再加倍；庄家为定约方先叫该花色者；明手为庄家同伴；首攻为庄家左手敌方。
   - **合约分**：按 `wbf-laws-2017` 与 `standard-duplicate` 口径；`scoringProfile` 只记标识，不硬编码奖分常数。
   - **裁判调整/取消/未完成**：见 6.8.1 与 6.11；三态区分 `CANCELLED / ADJUSTED / INCOMPLETE`，不得用 0 分表示无成绩。
6. **裁判裁决与引擎自动判罚边界（P0-3）**：引擎只自动判"合法/非法输入并拦截"；涉及撤回、违规出牌、程序罚分、调整分、取消副的裁决**一律转裁判**（`DIRECTOR_REQUIRED`），引擎不自动赋分。裁判操作见 6.8。
7. **验收用例**：附录 D 扩为规则验收用例集（正向/反向、合法/非法、预期状态/结果），覆盖叫牌轮次、加倍/再加倍合法性、庄家判定、首攻、跟牌义务、局况奖分、边界分。

### 6.3 超时与托管（参数由系统管理员设置）
1. **叫牌超时**：默认 2 分钟，超时自动判 Pass，记录"超时自动 Pass"。
2. **出牌超时**：默认 2 分钟，超时判托管——降智 AI 接替本副剩余操作，界面标注"托管中"；真人副间恢复。
3. 超时参数管理员全局配置；计时按"每次轮到该座位"独立计算，服务端权威。
4. 托管/超时事件写入日志，回放可见。
5. 出牌托管本副内不打断；真人重连后本副结束再恢复，未恢复继续 AI。

### 6.4 AI 机器人模块与叫牌体系执行

1. AI 占座自动叫牌/出牌，支持简易/普通/高手与降智托管档。
2. **AI 单步决策时限（P95）**：简易 <100ms、普通 <800ms、高手 <2s、降智托管 <200ms。DDS 超时/失败回退启发式，不阻塞对局；全 AI 由服务端定时驱动。
3. **叫牌体系执行边界**：
   - AI 只执行**内置且已编译**体系（V0.7：精确制默认、自然制演示级）。
   - 人类搭档声明内置体系 → AI 按该体系执行（`effectiveSystem = declaredSystem`）。
   - 人类搭档声明上传/未编译体系 → AI **回退系统默认精确制**，`effectiveSystem = precision`、`fallbackToDefault=true`，披露面板与成绩单标注"实际执行体系：系统默认精确制"；写 `SYSTEM_FALLBACK_TO_DEFAULT`（info）事件。
   - 双 AI → 系统默认精确制，`overlay=false`。
4. **体系声明与解释**（详见 6.10）：浮层、提醒、披露面板按**叫牌方 `effectiveSystem`** 生成解释；`explanationSource` 标注 `builtin / uploaded-text / system-inferred`；防守方各自按自己体系理解，不强制全桌统一。
5. 叫牌体系可配置；V0.7 默认精确制，自然制演示级。
6. 室主可副间换人/换 AI、调难度；**体系声明 Session 内锁定**（`practice` 房除外，6.10.5）。
7. AI 决策可复现：相同 `rulesetId`、`randomness=0`（或相同 `rngSeed`）下叫牌决策可重算；DDS 深度打牌不承诺重算一致。
8. **AI 三类验收（P1）**：
   - **时延验收**：按 2 的 P95 目标，测试条件见测试计划；
   - **决策质量验收**：以固定种子（如 `2026`）跑 1000 副基准，记录平均 IMP/副、绝对偏差、漏局/漏贯/超叫/流局数；质量阈值由测试计划设定，SRS 只要求"可量化、可回归"；
   - **超时回退验收**：DDS 超时/失败必须回退启发式且不阻塞对局，回退事件写日志；回退率超阈值告警（阈值测试计划定）。

### 6.5 掉线与断线重连
1. 真人掉线保留座位；短时重连回对局。
2. 超时未重连按配置处理（默认自动 AI 接管）；重连窗口默认 60s。接管事件写日志。
3. 重连成功可副间收回座位；本副不打断。
4. 托管、重连、恢复写入事件流。
5. **旁观者替补**：室主/裁判可邀请本室旁观者替补（2.6.4）；替补不改变已打副原始分。

### 6.6 旁观
旁观者进入观战席，可切换观战桌；**不可见四家手牌，可见明手牌、叫牌与出牌记录**；队式赛可分别查看各桌。旁观/转播频道与玩家频道隔离；使用独立 `audience=SPECTATORS_DELAYED`，不与 `TABLE` 混流。

### 6.7 回放与日志
1. 回放：单副/整盘，JSON 事件流（事件类型 + 时间戳 + 载荷），服务端另存快照支持 `lastSeq` 重连与断点回放。事件信封、受众投影、损失报告按交换规范 v2。
2. 对局日志：保存全部叫牌、出牌、超时、托管、换人、分数修改、管理员干预；**在线保存 1 年**，到期前 30 天提示导出，到期按 9.6 清理。
3. **可见时点**：同一 `Deal` 所有 `TableBoard` 完成后开放该副回放/导出；整盘在 `Session` 结束后开放；对局中禁止导出未完成牌。
4. **跨桌隔离与转播释放**：参赛玩家对局中不能看到另一桌定局/结果/进度；转播/旁观释放**同时满足** (a) 距该副在本桌结束 ≥30 秒（可配）；(b) 该副已完成后至少延迟一副（不可关）。服务端按 `audience=SPECTATORS_DELAYED` 投影，聊天隔离。
5. **版本兼容（P1）**：事件 `schemaVersion` 升级须提供迁移器；旧事件可读、可重放；损坏快照可回退到最近一致快照 + 事件重放；重算结果与历史不一致时以"历史快照为准、新算结果标记差异"并告警，不静默覆盖；重放器兼容旧版本，导出文件带 `schemaVersion` 与 `producerVersion`。

### 6.8 管理员（裁判）干预操作
所有操作需填写原因，记录操作人、时间、前后状态，写日志与回放；**敏感操作二次确认**（2.2）。

#### 6.8.1 中止某桌某副
冻结 → 标记 → 三选一：
- **取消该副**：`TableBoard.status=CANCELLED`；`rawScore=null`、`imp=null`（**不得写 0**）；`derived.artificialAverage` 按赛制配置单独保存并标 `artificial=true`；写审计；`SessionBoard` 重算。
- **判调整分**：保留 `originalRawScore`，写 `rawScore`（NS 视角），记录 `adjustReason / actor / at / beforeValue / afterValue`；**重算该 `Deal` 的 `SessionBoard`**；再次调整保留 `adjustHistory`。
- **重新发牌**：仅叫牌阶段未出牌；单桌新建 `Deal`；队式赛必须全桌一起重发，否则只能取消或调整；旧叫牌作废保留审计。

#### 6.8.2 其他干预
2. **踢出选手**：强制退出，本盘不可重入；对局中座位按断线规则处理（保留或 AI 接管，管理员当场选）。
3. **警告**：界面提示 + 日志。
4. **扣分/调整分**：扣 IMP/合约分或调原始分，填原因，记录前后值，重算 `SessionBoard`。
5. **暂停某桌**：冻结整桌（倒计时暂停），处理后恢复或判罚。
6. **查看所有牌室与对局**：管理面板浏览。
7. **响应呼叫**：进入目标桌管理态。
8. **替补邀请**：发起旁观者替补（2.6.4），写审计。

#### 6.8.3 误操作恢复（P1）
- 改分、踢人、暂停桌在 **5 分钟内**可由操作管理员或更高权限管理员撤销（`director.undo` 事件，引用原事件 `corrects`）；超过 5 分钟须走争议复核。
- 撤销不删除原事件，追加更正事件；审计保留双向记录。

#### 6.8.4 争议复核（P1）
- 参赛者可对裁判操作提出复核申请（填写理由）；复核由另一管理员（或产品负责人）处理；复核结论写审计。
- 单 `admin` 阶段无第二管理员时，复核记录"单人复核，已知风险"，并在 10 待确定第 2 项跟踪。

> 判罚依据参考 WBF 规则 90/91/86；引擎不自动赋分，裁决转裁判（6.2.6）。

### 6.9 队式赛转播观战
1. 队式赛可开启转播；旁观者通过"转播观战"进入。
2. 可切换各桌（不看手牌），显示跨桌实时对比栏（进度、定约、结果对比）。
3. 手牌不可见沿用 6.6；服务端按 `audience=SPECTATORS_DELAYED` 投影推送，释放条件见 6.7.4；转播聊天与玩家频道隔离。

### 6.10 叫牌体系声明、解释与披露

#### 6.10.1 声明主体与时点
1. **主体**：按 pair 声明（单桌南北/东西；队式赛每队每桌一对，按 4.2 对位表挂载）。
2. **时点**：Session 开局前；Session 内锁定，副间不可改。
3. **锁定**：`Session.systemDeclarations[pairId]` 含 `declaredSystem / declaredBy / declaredAt`；Session 进行中不可修改。
4. **未声明**：按系统默认精确制，标注"未声明，按系统默认"，写快照。

#### 6.10.2 三层分离与场景矩阵（P0-5 修订）

每 pair 每副记录三个字段：`declaredSystem`（声明）、`effectiveSystem`（AI 实际执行，真人+真人时为 null）、`explanationSource`（解释来源）。

| 场景 | declaredSystem | effectiveSystem | explanationSource | 披露面板显示 |
|---|---|---|---|---|
| 人类 + 人类 | 该 pair 声明 | `null`（无 AI） | 人类自主；提醒由叫牌方人类触发，标注 `user-provided` | 声明体系 + "人类自主，系统不解释" |
| 人类 + AI（声明内置） | 内置体系 | 同 declaredSystem | `builtin` | 声明体系 + "AI 按该体系执行" |
| 人类 + AI（声明上传/未编译） | 上传体系 | `precision`（回退） | `uploaded-text`（用户原文）或 `builtin`（回退后 AI 叫品） | **"声明体系：X（仅解释）；实际执行体系：系统默认精确制"** |
| AI + AI | 系统默认 | `precision` | `builtin` | "系统默认精确制" |
| 对手 pair | 各自 pair 独立 | 各自独立 | 各自独立 | 可查对方三层信息 |

**强制披露**：AI 回退默认时，披露面板必须显示 `effectiveSystem`，不得只显示 `declaredSystem`；成绩单与导出携带 `effectiveSystem / fallbackToDefault`。

#### 6.10.3 解释、提醒与披露
1. **解释权归叫牌方**：叫品含义由叫牌方 `effectiveSystem` 解释；`explanationSource` 标注来源：
   - `builtin`：系统内置规则生成，确定性解释；
   - `uploaded-text`：用户上传原文，标注"用户提供，未经系统验证"；
   - `system-inferred`：系统推断，标注"系统推断，仅供参考"。
2. **披露面板**：对手可查对方 `declaredSystem / effectiveSystem / explanationSource / source / version`；对应 WBF system card 披露义务。
3. **不强制全桌统一**：双方声明不同不视为冲突；每 pair 独立。
4. **上传体系解释**：V1 仅用于提醒浮层与披露面板；不编译、不执行；上传内容经敏感词与格式校验，`source=uploaded` 写快照。
5. **AI 与真人搭档实际约定不一致（P0-5）**：AI 只能执行内置体系；若真人实际采用与声明不同的约定，责任在真人搭档；系统在披露面板标注"AI 实际执行：<effectiveSystem>"，不保证与真人实际约定一致；该偏差写审计（`SYSTEM_DECLARATION_MISMATCH` warning）。

#### 6.10.4 上传体系的执行（V1 不做，单独立项）
1. 上传体系驱动 AI 须满足交换规范 v2 §9 门槛（可编译率 ≥90%、447 测试全绿、固定牌例决策一致、`rulesetId` 可复现）。
2. 上传体系需管理员审核/签名；AI 仅在 `practice` 或明确授权房间按上传体系执行。
3. 未达门槛前保持"仅解释"，不得宣称"AI 按上传体系叫牌"。

#### 6.10.5 逐副声明（仅练习房）
1. 仅 `practice` 允许逐副声明；该盘 `scoringEligibility=ineligible`。
2. 逐副声明写入每副 `TableBoard.engine.{declaredSystem, effectiveSystem, explanationSource}`；`SessionBoard` 按副重算不跨副合并。
3. `casual` / `competitive` 逐副声明返回 `SYSTEM_DECLARATION_LOCKED`。

#### 6.10.6 错误码与审计
- `SYSTEM_DECLARATION_LOCKED / SYSTEM_UPLOAD_INVALID / SYSTEM_UPLOAD_NOT_EXECUTABLE / SYSTEM_FALLBACK_TO_DEFAULT / SYSTEM_DECLARATION_MISMATCH`。
- 声明、锁定、回退、上传审核、声明与实际不一致均写审计；三层字段进入导出投影。

### 6.11 异常结算统一表（P0-4 / 语义问题 3 新增）

| 异常 | TableBoard | SessionBoard | teamImp | 能否再调整 | 能否重赛 | 整盘完成条件 |
|---|---|---|---|---|---|---|
| 正常完成 | PLAYED | COMPLETE | 计算 | 可（调整） | 否 | 计入 |
| 流局 | PASSED_OUT | COMPLETE | 按 0 分差计算 | 可 | 否 | 计入 |
| 取消副 | CANCELLED（rawScore=null） | CANCELLED | 不计算；`artificialAverage` 单独 | 可改判 ADJUSTED | 仅 `REOPENED` 后 | 不计入；若赛制要求 artificialAverage 计入 |
| 调整分 | ADJUSTED（保留 original） | ADJUSTED（重算） | 按调整后计算 | 可再次调整（保留历史） | 否 | 计入 |
| 缺桌 | INCOMPLETE | INCOMPLETE | 不计算 | 补打后可转 PLAYED | 可补打（非重赛） | 不计入，成绩单标注 |
| 超时未完成 | INCOMPLETE → 托管完成或裁判裁决 | 随 TableBoard | 随裁决 | 可 | 仅 `REOPENED` | 按裁决 |
| 重发失败 | 旧 TableBoard 标记 superseded | REDEAL_PENDING（Session 级） | 不计算直至恢复 | 否（须裁决） | 是（全桌） | 禁止结算直至裁决 |
| 已取消再调整 | CANCELLED → ADJUSTED | CANCELLED → ADJUSTED | 按调整后 | 可 | 否 | 计入 |
| 已调整再取消 | ADJUSTED → CANCELLED | ADJUSTED → CANCELLED | 不计算 | 可改判 | 否 | 不计入 |
| 一桌取消一桌完成 | CANCELLED + PLAYED | CANCELLED | 不计算 | 可改判 | 仅全桌 `REOPENED` | 不计入 |

**优先级规则**：`CANCELLED` 默认拒绝再次调整，须先 `REOPENED`（裁判重开，写审计）；`ADJUSTED` 可再次调整（保留 `adjustHistory`）或取消；重赛必须全桌 `REOPENED`，不得单桌重赛。

## 7 计分功能

### 7.1 计分模式（插件化）
1. **合约分**（每副必算）：按 WBF 规则与 `standard-duplicate`。
2. **队式 IMP**：跨桌同副分差换算，表 `wbf-2017`。
3. **MP/VP**：V1 不启用，仅保留字段。

### 7.2 计分引擎规则
1. 每副结束自动计算本副得分，计入南北/东西（或红蓝队）累计。
2. **手动修正**：`practice` 室主可改；`casual`/`competitive` 仅管理员（裁判调整分）。授权以 `roomNature` 为准；均填原因，记录前后值、操作人、时间；调整落 `TableBoard.rawScore` 保留 `originalRawScore`，重算 `SessionBoard`。
3. 展示：实时当前副得分 + 各方累计；队式赛跨桌比对与 IMP；结束后完整成绩单（定约、庄家、首攻、结果±墩、南北/东西得分、IMP 汇总、`scoringEligibility`、`effectiveSystem / fallbackToDefault`）。
4. 对局记录与回放 **在线保存 1 年**，可导出；到期清理见 9.6。

### 7.3 队式赛跨桌结算
1. 各桌打完当前副后按同副结果比对换算 IMP；某桌未完成等待或按 6.11 处理。
2. **公式（P0 修正）**：`teamImp = impTable(redTeamRaw)`，其中 `redTeamRaw = Σ(红队各桌红队视角原始分)`（代数和）；`blueTeamRaw` 仅展示，不参与换算；**逐副换算、逐副累加**；表版本 `wbf-2017`。
3. **体系快照**：`SessionBoard.engine` 记录各 `TableBoard` 的 `declaredSystem / effectiveSystem / explanationSource / rulesetId`；AI 回退默认时 `fallbackToDefault=true`，成绩单标注"实际执行体系：系统默认"，不改变分数。
4. 异常结算按 6.11 统一表。
5. 结算结果按角色投影展示——参赛玩家只看本桌与本方汇总，跨桌明细只对旁观/转播（延迟）和管理员；体系披露面板对所有参赛者开放（6.10.3）。

### 7.4 导出
1. **格式**：JSON 事件流、PBN、CSV（UTF-8 BOM，含每副明细与 IMP 汇总；V1 不含 MP/VP）。**交换契约以《桥牌规则与数据交换规范 v2》为正本**。
2. **方式**：单盘同步；全量/历史异步。
3. **权限**：玩家只能导出自己参与的对局；管理员导出需原因 + 审计；注销/匿名化数据按 9.6。
4. **时点**：与 6.7 一致——同一 `Deal` 所有桌完成后可导出该副，整盘 `Session` 结束后可导出；对局中禁导出未完成牌。
5. 大厅"最近对局记录"可查询导出本人对局；成绩单字段与界面一致；`scoringEligibility` 与 `practice` 标注。

## 8 权限与安全

1. **所有访问均需登录**；旁观者仅观战，不可见手牌、不可参与叫牌出牌。
2. 分数修改仅 `practice` 室主与管理员（裁判调整分）；`casual`/`competitive` 室主不可改。授权以持久化 `roomNature` 为准；所有修改留完整日志。
3. 密码强哈希；会话 Cookie `httpOnly + Secure + SameSite=Lax`；登录失败按账号 + IP 锁定；注册、昵称查询、导出限流；密码重置审计 + 会话撤销（2.1.5）。
4. 用户名/昵称归一化唯一；公开只显示昵称，用户名/邮箱仅本人和管理员；改名受 3 次上限、24h 冷却、对局中锁定、旧名 30 天保留。
5. 管理员操作全部留痕（操作人、时间、原因、前后状态）；**审计日志至少 3 年，只追加、不可由管理员删除**；查看暗手、导出等敏感操作双写审计（操作日志 + 事件流）。
6. WS 校验 Origin，HTTP 校验 CSRF；敏感词覆盖聊天（四层）、昵称、提醒；单 IP/设备连接数限制；聊天限频按 2.6.2（`userId` 主 + IP 辅，四层配额，超限 `CHAT_RATE_LIMITED` + 风控日志）；连接数阈值、配额、时间窗管理员配置；`X-Forwarded-For` 只在可信反向代理后使用；WS 聊天订阅按 `audience` 鉴权，断线重连重校验。
7. **服务端数据投影**：导出/回放服务端时点与归属鉴权，不靠前端隐藏；按角色投影，不把四家暗手推给无权限连接；**WS 订阅**按 `audience` 鉴权，断线重连重校验（撤销立即生效）；**跨桌隔离**：参赛玩家连接不接收其他 `tableId` 定局/结果/进度，服务端按 `tableId` 过滤；**管理员敏感操作**双写审计。
8. **隐私与部署**：公网 HTTPS；注册页隐私政策与同意；"导出我的数据"和"注销账号"入口；对局数据按 `Deal / TableBoard / SessionBoard` 归属，注销按 9.6。

### 8.9 字段级授权矩阵与统一鉴权（P0-6 新增）

**角色 × 数据字段矩阵**（`R`=可读，`W`=可写，`—`=不可见/不可写）：

| 数据字段 | 参赛玩家（本桌） | 参赛玩家（他桌） | 旁观者 | 转播（延迟） | 室主 | 管理员/裁判 |
|---|---|---|---|---|---|---|
| 本桌四家手牌（暗手） | 仅本人座位 `R` | — | — | — | — | `R`（留痕） |
| 本桌明手 | `R` | — | `R`（延迟后） | `R`（延迟后） | `R` | `R` |
| 本桌叫牌/出牌 | `R` | — | `R`（延迟后） | `R`（延迟后） | `R` | `R` |
| 他桌定约/结果/进度 | — | — | `R`（延迟后） | `R`（延迟后） | —（非本桌） | `R` |
| 体系披露（declared/effective/explanationSource） | `R`（对手 pair） | — | `R` | `R` | `R` | `R` |
| 原始分/IMP | `R`（本桌+本方汇总） | — | `R`（延迟后） | `R`（延迟后） | `R` | `R` |
| 成绩资格 scoringEligibility | `R`（结束后） | — | `R`（结束后） | `R`（结束后） | `R` | `R` |
| 审计日志 | — | — | — | — | — | `R` |
| 导出（含四手牌） | 仅本人参与、`POSTGAME` 释放后 | — | — | — | 本人参与 | `R` + 原因审计 |

**统一鉴权执行点（P0-6）**：
1. **HTTP 查询**：每个端点按矩阵返回字段子集；未授权字段不进入响应体（非前端隐藏）。
2. **WebSocket 推送**：每条事件按 `audience` 投影，服务端过滤后推送；客户端不得依赖"收到但隐藏"。
3. **回放**：回放接口按请求者角色投影，未释放副返回 `EXPORT_NOT_RELEASED`。
4. **导出**：服务端时点 + 归属鉴权；含四手牌导出标 `postGame:true` + `exportedBy` + `projection`。
5. **错误信息**：错误响应不得泄露未授权字段（如"他桌结果"）；统一错误码不携带敏感值。
6. **缓存**：服务端缓存与 CDN 缓存按 `audience` 分键；禁止跨角色共享缓存；缓存失效随权限撤销。
7. **延迟**：以**服务端权威时间**计算释放；副结束、跨桌进度不一致、重赛、取消副时按 6.7.4 与 6.11 释放或撤回。
8. **验收（P0-6）**：渗透测试必须证明未经授权的客户端（直连 WS/HTTP、改参数、重放令牌）拿不到隐藏手牌与未释放跨桌结果；测试用例入附录 D 安全用例集；此项为正式比赛上线安全门槛。

## 9 非功能需求

### 9.1 实时性与 AI 质量
操作广播 P95 ≤ 200ms（目标）；AI 单步 P95 按档（6.4.2）；超时倒计时服务端权威。DDS 超时/失败回退启发式，不把 20–30 秒客户端超时带入正式对局。**三类验收**（6.4.8）：时延验收、决策质量验收（固定种子 1000 副基准）、超时回退验收；测试条件见测试计划。

### 9.2 平台
**仅网页端**，暂不适配移动端。

### 9.3 数据与持久化
1. 全部服务端持久化；`userId` 贯穿；按 `Deal → TableBoard → SessionBoard` 持久化，`SessionBoard` 可重算（快照 5.3.6）。
2. 事件流 + 快照支持 `lastSeq` 重连与断点回放；事件带 `version`；**版本兼容见 6.7.5**（迁移器、旧事件可读、损坏快照恢复、重算不一致告警）；服务重启可恢复进行中全 AI 对局。
3. 在线留存按 9.6；到期前 30 天提示导出。

### 9.4 异常处理
掉线保留座位、超时按配置接管；全 AI 服务端驱动；写操作失败返回明确错误码不产生半完成；全桌重发失败整体回滚或 `REDEAL_PENDING`（5.3.4）；并发裁判操作串行化（5.3.7）；状态转换按 5.5。

### 9.5 可配置（系统管理员）
超时时长、降智档位、等候区上限、牌室销毁超时、举手超时、注册/验证码开关、留存期提醒阈值、转播延迟秒数、IMP 表版本、聊天分层配额（默认 2.6.2）、连续超限临时禁言阈值、快捷短语卡集、连接数阈值等。

| 对局事件/回放/成绩单 | 盘结束起 **365 天** | 到期前 30 天提醒导出 |

## 附录 A：V0.7 变更验收要点

5. **改名次数**：1–3 次成功，第 4 次 `NICKNAME_CHANGE_LIMIT`；失败不计数；24h 冷却 `NICKNAME_COOLDOWN`。

## 附录 D：规则验收用例集（P0-3 扩写）

> 规则版本 `wbf-laws-2017`；引擎只判合法/非法并拦截，裁决转裁判（`DIRECTOR_REQUIRED`）。

**D-1 叫牌结束**：`1NT PASS PASS PASS` 结束；四 Pass 流局；`1NT X PASS PASS PASS` 结束；导出 PBN 不追加 Pass；`AP` 展开不超所需 Pass。
**D-2 座位方向**：ME=S，顺序 N/E/S/W，PAR=N、RHO=E、LHO=W；同伴 N 开 1NT 后 E（RHO）行动。
**D-3 叫牌合法性**：非法叫品 `BID_ILLEGAL`；非法加倍 `DOUBLE_ILLEGAL`；非法再加倍 `REDOUBLE_ILLEGAL`；叫牌轮次错误拦截。
**D-4 定约与庄家**：实质叫品 + 加倍/再加倍；庄家为定约方先叫该花色者；明手为庄家同伴；首攻为庄家左手敌方；用例覆盖各花色与 NT。
**D-5 出牌合法性**：跟牌义务 `PLAY_ILLEGAL`；垫牌合法；首攻限制；撤回/违规出牌 `PLAY_REVOKE_PENDING` → `DIRECTOR_REQUIRED`。
**D-6 赢墩与结算**：赢墩统计；合约分、加倍/再加倍、超墩、宕墩、局况、满贯奖分按 `wbf-laws-2017`；边界分用例。
**D-7 流局**：`PASSED_OUT`，`nsRaw=0`，贴点由 `hcp` 派生不写原始分。
**D-8 裁判边界**：引擎不自动赋分；撤回/违规/程序罚分/调整分/取消副一律 `DIRECTOR_REQUIRED`。
**D-9 安全用例（P0-6）**：直连 WS 订阅他桌暗手被拒；改 `tableId` 参数被拒；重放令牌被拒；未释放副导出 `EXPORT_NOT_RELEASED`；错误信息不含他桌结果；缓存不跨角色共享。
