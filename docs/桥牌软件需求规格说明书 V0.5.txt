## 0 术语与数据分层

全文统一术语如下：

| 术语 | 英文 | 定义 |
|---|---|---|
| 大厅 | Lobby | 玩家登录后的主入口，含在线名单、牌室列表、聊天、管理员入口 |
| 牌室 | Room | 室主建立的虚拟空间，含名称、玩法、总副数等配置 |
| 盘 | Session | 一次连续对局单元（一次"开始"到"结束"），一盘含若干副 |
| 副 | Board | 桥牌的一副牌（发牌→叫牌→出牌→结算） |
| 桌 | Table | 实际打牌的 4 席位单元；队式赛可有多桌 |
| 席位 | Seat | 桌内的北/南/东/西（或队式赛对应方位） |
| 阵营 | Camp | 队式赛的红方/蓝方等候区，非队式赛不需要 |
| 账号 | Account | 稳定身份，含邮箱、用户名、昵称、密码哈希、角色与状态；`userId` 全局唯一 |
| 用户名 | Username | 登录标识，归一化后全局唯一、不可修改、公开不可见 |
| 昵称 | Nickname | 公开显示名，归一化后全局唯一、可修改且终身最多 3 次 |
| 玩家 | Player | 注册账号登录后的真人；账号有稳定 userId、唯一用户名和可改昵称 |
| 管理员/裁判 | Admin / Director | 系统管理员账号，承担裁判职能（当前阶段的过渡方案） |

**数据模型分层**：`Account → Lobby → Room → Session → Board → Table → Seat`。`Account` 是全局身份，独立于大厅与牌室，所有对局、成绩单、回放、权限和审计均挂到稳定 `userId`；单桌与多桌队式赛共用同一套 `Room/Session/Board/Table/Seat` 结构。计分策略（合约分/MP/IMP）以插件方式挂载。数据模型含 `userId`、`username`、`nickname`、`role`（玩家/管理员/裁判）、`pair`（对）等字段；用户名/昵称的归一化查重与旧名保留由 `NameRegistry` 承担（见 2.1.6）。

## 1 概述

### 1.1 产品目标
实现线上桥牌对局系统：玩家注册账号并登录后进入大厅，在大厅查看在线名单与公开牌室列表、进入牌室；室主命名牌室、定义玩法与总副数；支持单桌 4 人玩法与红蓝阵营队式赛；选手可自行落座或由室主拖拽分配，举手准备；室主判断后手动开局，空位按组队需要自动补 AI；叫牌/出牌超时自动判 Pass 或降智 AI 托管；系统管理员（裁判）可对比赛进程进行干预；自动计分、对局记录与回放在线保存 **1 年**并可导出；队式赛提供转播观战。

### 1.2 范围
- **包含**：注册/登录/个人资料（邮箱、用户名、昵称、密码、改昵称）、会话与多设备、大厅（在线名单/牌室列表/聊天/管理员入口）、牌室创建与配置、单桌玩法、队式赛（红蓝阵营、结对、多桌同牌、跨桌 IMP）、等候区与座位管理、举手准备、手动开局与 AI 补位、叫牌/出牌超时与托管、合约分/MP/IMP 计分、管理员干预（中止副/踢出/警告/扣分/暂停）、呼叫管理员、转播观战、对局日志与回放、旁观、室主权限移交、最近对局记录、成绩单与 JSON/PBN/CSV 导出。
- **不包含**：付费会员体系（演示期仅提供“推荐 + 浮动层解释”前 50 副试用，见 9.6）、音视频、移动端适配、双人赛多轮编排、瑞士移位、梯级挑战赛、导入预发固定牌型（预留接口）、独立裁判账号体系（以系统管理员代行，角色字段已预留）、邮箱验证与邮件自助找回（V1 由管理员重置密码）。

### 1.3 设计原则
1. **一次设计完成**：功能边界一次冻结，数据模型一次做对，不设"一期/二期"割裂。
2. **真人优先、AI 兜底**：任何席位缺失都能由 AI 补齐，保证对局可推进。
3. **原子开局**：开局一次性完成"移出未举手者→补 AI→校验最低真人数→锁定→发牌"，不出现中间态。
4. **副中锁定、副间可调**：一副牌进行中禁止换座/换人，副与副之间允许室主调整。
5. **管理可干预、操作可追溯**：管理员所有干预操作均留日志，可回放查看。

## 2 玩家账号、大厅与管理角色

### 2.1 注册、登录与命名（V0.5 修订）

> 本节取代 V0.4 的“昵称入室/匿名临时 userId”模型。账号是稳定身份，所有对局、成绩单、回放与权限均挂在 `userId` 上；昵称只是可改的公开显示名。

#### 2.1.1 注册与登录
1. 注册必填：**邮箱、用户名、昵称、密码**。
2. 邮箱：必填、唯一、规范化为小写、可修改、**V0.5 暂不验证**；预留 `emailVerifiedAt`，未验证前不能用于自助找回。
3. 登录：**用户名 + 密码**；邮箱不作为登录名。
4. 密码：至少 8 位，禁止与用户名/昵称相同；服务端使用强哈希（Argon2id/bcrypt）存储，不存明文、不写日志。
5. 注册风控：图形验证码 + 每 IP 每小时最多 5 次注册 + 登录失败锁定；内网演示可关闭。
6. 未登录用户只能访问注册/登录页；**旁观与聊天也必须登录**。
7. 忘记密码：V1 仅管理员重置，生成临时密码并强制首次登录修改；不做邮件自助找回。

#### 2.1.2 用户名（登录标识，公开不可见）
1. 长度 **3–12 位**，正则 `^[A-Za-z][A-Za-z0-9_]{2,11}$`：字母开头，只允许字母、数字、下划线。
2. 归一化：`NFKC` + 转小写 + 去首尾空白后查重；`Alice`、`alice`、`Ａlice` 视为同一用户名。
3. 全局唯一；并发注册/改名由服务端唯一约束裁决，冲突返回 `409`。
4. 保留名（大小写不敏感、可配置）：`admin`、`administrator`、`support`、`system`、`root`、`bridge`、`null`、`undefined` 等。
5. 用户不可修改；管理员可纠正明显 typo，必须填写原因并写审计，不改变 `userId`。
6. 只对本人和管理员可见；公开界面只显示昵称。

#### 2.1.3 昵称（公开显示名）
1. 长度：至少 2 个字符、最多 12 个显示宽度。汉字/全角按 2，ASCII 字母/数字/下划线/连字符/空格按 1；即最多 6 个汉字或 12 个英文字母；emoji 不支持。
2. 宽度按 `NFKC` 归一化后的字符串计算（全角 `Ａ` → `A`，按 1 计）。
3. 允许中文、英文字母、数字、下划线、连字符、单词间单个空格；不允许首尾空格、连续空格、控制字符、零宽字符、emoji。
4. 归一化：`NFKC` + 去首尾空白 + 折叠连续空格 + 大小写不敏感后查重；**保留显示大小写**。
5. 归一化后**全局唯一**；与用户名是两个独立命名空间；两者都禁用保留名。
6. 昵称经敏感词过滤（与聊天共用词库）；管理员可强制改名。

#### 2.1.4 改名规则
1. 终身最多 **3 次**；注册时的初始昵称不计次；校验失败/请求被拒不计次；管理员强制改名不计入用户的 3 次。
2. 冷却：成功改名后 **24 小时**内不可再次改名；成功后 `nicknameChangeCount + 1`。
3. 对局中禁止改名：用户处于 `starting / playing / paused` 且已落座时返回 `NICKNAME_LOCKED_IN_SESSION`；大厅、等候区、旁观时可改。
4. 旧昵称保留 **30 天**：进入保留表，30 天内其他账号不可使用；本人可改回，但仍消耗一次改名次数；到期释放。
5. 日志/回放/成绩单保存**当时昵称快照**；个人资料页显示当前昵称。

#### 2.1.5 会话与账号安全
1. 会话 Cookie：`httpOnly + Secure + SameSite=Lax`；默认 7 天，“记住我”30 天；允许多设备登录，但**同一牌室只能占一个座位**。
2. 登录失败锁定（按账号 + IP）、注册限流、昵称可用性查询限流（防批量枚举）。
3. 管理员引导账号：单个 `admin`，初始密码从环境变量或首次启动生成，不入库明文、不进 Git；首次登录强制改密；公网部署禁止固定简单密码。
4. 角色（`player/admin`）保存在服务端会话/数据库，客户端不可自报；所有管理接口服务端鉴权。
5. 用户名/昵称的并发注册、改名只能有一个成功，其余返回 `409` + 明确错误码。

#### 2.1.6 账号状态、注销与命名查重
1. 管理员可封号/解封；封号后会话立即失效，座位按掉线规则处理。
2. 用户可申请注销，**30 天冷静期**；冷静期内可撤销；期满后账号资料匿名化/删除，对局数据按 9.6 处理。
3. 连续 2 年未登录先提醒，再按注销策略处理。
4. 账号与命名相关表：

```text
Account
  id, email, emailVerifiedAt?, passwordHash,
  username, usernameNormalized,
  nickname, nicknameNormalized,
  nicknameChangeCount, nicknameChangedAt,
  role, status, createdAt, lastLoginAt

NicknameChange
  accountId, oldNickname, newNickname,
  changedAt, actorType (user|admin), reason
```

5. 统一用 `NameRegistry` 表承担命名查重与旧名保留：

```text
NameRegistry
  kind (username|nickname)
  normalized
  ownerAccountId
  status (active|reserved)
  reservedUntil
  UNIQUE(kind, normalized)
```

6. 错误码：
   - `USERNAME_INVALID` / `USERNAME_TAKEN` / `USERNAME_RESERVED`
   - `NICKNAME_INVALID` / `NICKNAME_TAKEN` / `NICKNAME_RESERVED`
   - `NICKNAME_COOLDOWN` / `NICKNAME_CHANGE_LIMIT` / `NICKNAME_LOCKED_IN_SESSION`

### 2.2 角色与权限
| 角色 | 权限 |
|---|---|
| 系统管理员/裁判 | 响应呼叫、中止某桌某副、踢出选手、警告、扣分/调整分、暂停某桌、查看所有牌室与对局、进入任意牌室（管理态）、重置密码、封号/解封 |
| 室主 | 命名/配置牌室、分配阵营、拖拽上座/拽起、开始对局、副间换人换 AI、设置 AI 难度、踢人、解散牌室、修改分数（留日志）、移交室主 |
| 玩家（已登录） | 入室、自落座/离座、举手/取消举手、呼叫管理员、退出牌室、聊天、查看本人最近对局与导出本人参与的对局 |
| 旁观者（已登录） | 进入观战席、切换观战桌、看明手与叫牌出牌记录，**不可见四家手牌**、不可参与叫牌出牌 |

> 说明：V0.5 起所有角色（含旁观者、聊天）均须登录；角色由服务端会话/数据库决定，客户端不可自报。“裁判”仍由系统管理员账号承担，为**过渡方案**；未来拆分独立裁判角色时沿用 `role` 字段。

### 2.3 室主权限移交
1. 室主退出或掉线超时，权限移交给在场最早入室的真人。
2. 无可移交真人时牌室"冻结"：不能开局、不能开新盘，但当前副允许打完并结算。
3. 移交事件写入牌室日志。

### 2.4 大厅功能（V0.4 新增）
1. **在线玩家名单**：展示当前在线玩家，字段含昵称、状态（大厅中/在牌室/对局中/旁观中）、所在牌室名称（若在室内）；支持按昵称搜索。
2. **在线人数统计**：按玩法分类展示在线人数（单桌玩法/队式赛），辅助判断活跃度。
3. **公开牌室列表**：展示牌室名称、玩法、当前人数/上限、状态（等待/对局中）；点击直接进入等候区（无需审批）。
4. **私人牌室**：不在列表展示，凭邀请码/链接（可设密码）进入。
5. **大厅聊天区**：全局文字聊天，敏感词过滤。
6. **管理员入口**：大厅顶部为系统管理员提供独立入口，进入管理面板（见 6.8）。
7. **最近对局记录**：玩家可查看自己近期参与的对局列表（按时间倒序），点击进入成绩单/回放（按稳定 `userId` 查询；对局中不展示未完成牌的结果）。

### 2.5 呼叫管理员（V0.4 新增）
1. 牌室界面与对局界面均设【呼叫裁判】按钮。
2. 点击后向在线管理员推送通知，含牌室名、桌号、呼叫者昵称、简要事由（可选填）。
3. 当前桌显示"已呼叫裁判，等待处理"状态；管理员响应后以旁观者身份+管理权限进入该桌处理。
4. 暂无在线管理员时提示"管理员不在线，请稍后或在大厅留言"；呼叫记录写入日志。

## 3 牌室设计

### 3.1 牌室创建与配置
室主创建牌室时设定：
- **牌室名称**（必填，室主命名）、对局备注（可选）；
- **玩法类型**：`单桌4人标准桥牌` / `队式赛（红蓝阵营，支持多桌）`；
- **总副数**：自定义（如 8/12/16 副）或"不限副数，手动结束"；
- **最低真人数**（开局门槛，见 5.1）；
- **计分模式**：合约分（必选）；MP / IMP（队式赛或双人赛场景可选）；
- **AI 难度**：简易/普通/高手，可全局默认、可按座位单独设置；
- **断线接管策略**：`超时自动 AI 接管` / `保留座位等待室主决定`（默认前者）；
- **是否允许旁观**（开关）；**是否允许转播**（队式赛开关）；
- **房间密码**（可选，私人牌室用）；
- **聊天开关**、等候区上限等。

### 3.2 牌室加入
公开牌室空位即可直接进入等候区；私人牌室凭邀请码/密码进入。等候区人数设可配置上限（默认 20，室主可调）。

### 3.3 牌室状态流转
```
登录进入大厅 → 创建或进入牌室（等候区/阵营区） → 落座/拖拽分配 → 举手准备
  → 室主判断后点击【开始】（原子操作：移出未举手者→补AI→校验→锁定→发牌）
  → 对局进行中（逐副：叫牌→出牌→结算） → 副间可调整座位/换AI
  → 达到总副数或室主结束 → 生成成绩单与回放 → 可开下一盘 / 解散牌室
```

### 3.4 牌室界面布局
**A. 等候/准备界面（未开局）**
- 单桌玩法：统一【等候区】+【牌桌座位面板（北/南/东/西）】，标注「真人」/「AI(等级X)」/「空位」。
- 队式赛玩法：【红方阵营等候区】+【蓝方阵营等候区】+ 各桌座位面板；室主可在阵营内**结对（固定搭档）**，结对后上座自动按对位分配。
- 操作：选手可**自落座**（落座即锁定该席，防抢座）；室主可**拖拽上座**、可**拽起已落座者**（拽起后其举手状态重置，座位释放）。
- 举手按钮：真人点击【举手】进入准备态，可【取消举手】；AI 落座即视为已准备。
- 房间设置面板、聊天框、**【呼叫裁判】按钮**。
- 室主可见【开始】按钮，点击前弹确认（显示真人/AI 分布与最低真人数校验结果）。

**B. 对局界面**
- 牌桌可视化：四方位手牌、叫牌区、出牌区、明手摊牌；
- 叫牌面板：pass、加倍、再加倍、1C~7NT 等完整叫品；叫牌面板含可选【提醒】按钮（向对手发送简短约定叫说明，内容仅对手可见）；
- 实时计分面板：当前副得分、各方累计；队式赛显示跨桌比对与 IMP；
- 超时倒计时提示（叫牌/出牌）；
- **【呼叫裁判】按钮**与"等待裁判"状态提示；
- 队式赛：**转播观战入口**（见 6.9）。

### 3.5 牌室生命周期
1. 牌室持续存在，直到：室主手动解散 / 无真人在场且当前盘结束后超时（默认 30 分钟，可配置）自动销毁。
2. 对局中只要 4 席位（真人+AI）齐全，对局可持续推进，不要求真人在场；全 AI 对局由**服务端事件/定时器驱动自动推进**，不依赖前端在线。
3. 全 AI 对局默认标注"练习"，不计入正式成绩；盘内曾有真人参与则该盘计入。

---

## 4 组队与座位机制

### 4.1 单桌 4 人玩法
1. 固定 4 席位：北/南/东/西；南北一队、东西一队；副内搭档固定。
2. 选手自落座或室主拖拽分配；室主可拽起重排。
3. 空位在开局时由 AI 按**成对补位**规则补齐（见 4.4）。
4. 换人/换 AI 仅允许在副与副之间，副中锁定；换人不重置队伍累计分（累计分归属南北/东西席位对）。

### 4.2 队式赛玩法（红蓝阵营，多桌）
1. 牌室分红方阵营等候区与蓝方阵营等候区；每方席位需求 = 2 × 桌数。
2. 室主在各阵营内结对（固定搭档），结对后上座自动按对位分配到不同桌的南北/东西。
3. **同牌分发**：各桌打同一副牌型——牌室维护当前副牌型，开局分发到所有桌，保证可比。
4. **跨桌比对**：每副各桌打完后按同副结果比对换算 IMP 计入队总分；某桌未完成时等待或按超时规则处理。
5. 队式赛至少支持 2 桌（每方 4 人）；单桌队式退化为普通对局。

### 4.3 举手与超时离座
1. 落座后真人点击【举手】进入准备态，可取消。
2. **举手超时**：从落座（或室主点"开始准备"）起算，默认 60s（管理员可配），超时未举手则**自动离座回等候区**，座位释放。
3. 室主拽起已举手者，其准备态重置。
4. AI 落座即视为已准备，不参与举手超时。

### 4.4 AI 补位规则
1. **成对补位优先**：某方出现空位时优先成对补 AI，保证搭档完整。
2. **单空位处理**：某方仅剩一个空位时，补 1 个 AI 与该方真人搭档，界面标注"AI 搭档"。
3. AI 难度按全局设置或该座位单独设置。
4. 补位在开局原子操作中完成，补位后再次校验最低真人数。

## 5 开局规则

### 5.1 室主手动判断开局
"大部分落座即开局"由**室主自行判断并点击【开始】**，系统不强制自动开局。系统仅提供**最低真人数**硬门槛校验：
- 单桌玩法：默认至少 2 名真人（可配）；
- 队式赛：每方至少 1 名真人（可配）；
- 不满足门槛时【开始】置灰并提示原因；满足时允许开局（未落座/未举手空位由 AI 补）。

### 5.2 开局原子操作
点击【开始】后服务端在一个事务内完成：①移出所有未举手真人回等候区；②按 4.4 规则为空位补 AI；③校验最低真人数；④锁定座位（副中不可变）；⑤发牌（队式赛分发同一副牌型到各桌）；⑥广播开局。任一步失败整体回滚，牌室保持开局前状态并提示。

### 5.3 总副数与结束
达到设定总副数自动结束本盘；"不限副数"时由室主手动结束。结束后生成成绩单与回放，可开下一盘。

## 6 对局核心功能

### 6.1 发牌与明手
随机洗牌、四家分发；庄家确定后明手自动摊牌；队式赛各桌同副牌型一致。

### 6.2 叫牌与出牌
1. 完整桥牌叫品，叫牌顺序校验，非法叫品拦截。
2. 轮次出牌，出牌合法性校验，自动统计赢墩。
3. 叫牌面板【提醒】按钮：向对手发送简短约定叫说明（仅对手可见），内容入日志。
4. 所有叫牌/出牌写入对局日志。

### 6.3 超时与托管（参数由系统管理员设置）
1. **叫牌超时**：默认 2 分钟（管理员可配），超时**自动判为 Pass**，记录"超时自动 Pass"。
2. **出牌超时**：默认 2 分钟（管理员可配），超时**判为托管**——由**降智 AI 接替**该席位完成本副剩余操作（降智档位可配，如"简易"），界面标注"托管中"；真人可在副间恢复操作（副中接管后不打断）。
3. 超时参数（叫牌/出牌时长、降智档位）为系统管理员全局配置，室主不可改；界面显示倒计时。
4. 托管/超时事件写入对局日志，回放可见。

### 6.4 AI 机器人模块
1. AI 占座时自动完成叫牌、出牌，支持简易/普通/高手多档位与"降智托管"档。
2. AI 单步决策时限 ≤ 2s（服务端保障），全 AI 对局由服务端定时驱动推进。
3. 叫牌体系：统一采用**自然叫牌体系（规则式）+ 出牌启发式**作为基础实现；精确体系等作为可扩展配置项预留。
4. 室主可在副间替换座位真人/AI、调整 AI 难度。

### 6.5 掉线与断线重连
1. 真人掉线保留座位；短时重连回到对局。
2. 超时未重连按牌室配置处理：`自动 AI 接管` 或 `保留等待室主决定`（默认前者）；接管事件写日志。
3. 重连成功可收回座位（副间），接管 AI 退出。

### 6.6 旁观
旁观者进入观战席，可切换观战桌；**不可见四家手牌，可见明手牌、叫牌与出牌记录**；队式赛旁观者可分别查看各桌。

### 6.7 回放与日志
1. 回放：单副/整盘回放，查看叫牌、出牌全过程；格式采用 **JSON 事件流**（事件类型 + 时间戳 + 载荷：叫牌/出牌/提醒/换人/托管/改分/裁判干预），服务端另存快照以支持 `lastSeq` 重连与断点回放。
2. 对局日志：保存全部叫牌、出牌、超时、托管、换人、分数修改、管理员干预记录；**在线保存 1 年（自盘结束起）**，到期前 30 天提示可导出，到期后按 9.6 清理。
3. **回放/导出的可见时点（防作弊）**：同一 `Deal` 的所有 `TableBoard` 完成后才开放该副回放/导出；整盘在 `Session` 结束后开放；对局中禁止导出当前未完成牌。
4. **跨桌信息隔离**：参赛玩家在对局中不能看到另一桌的定局、结果或进度；跨桌信息只对旁观/转播开放，并按配置延迟推送。

### 6.8 管理员（裁判）干预操作（V0.4 新增）
管理员在大厅管理面板或牌室管理态可执行以下操作，**所有操作需填写原因，记录操作人、时间、前后状态，写入日志与回放**：

1. **中止某桌某副**：选中目标桌 → 点击"中止当前副" → 系统立即冻结该桌叫牌/出牌 → 标记该副"裁判中止" → 管理员选择处理方式：
   - **取消该副**（双方平均分）；
   - **判调整分**（手动输入南北/东西得分）；
   - **重新发牌**（仅限叫牌阶段；已出牌则不可重发）。
2. **踢出选手**：在牌室成员列表中选中玩家 → "移出牌室"；被踢者强制退出当前牌室，本盘内不可重新加入；若正在对局中，其座位按断线规则处理（保留等待或 AI 接管，由管理员当场选择）。
3. **警告**：向选手发送警告（界面提示 + 日志）。
4. **扣分/调整分**：扣除 VP/IMP/合约分，或直接修改某桌某副得分（需填原因，记录前后值）。
5. **暂停某桌**：冻结整桌对局（叫牌/出牌倒计时暂停），用于处理争议；处理后恢复或判罚。
6. **查看所有牌室与对局**：管理面板可浏览全部牌室状态、对局进程、日志。
7. **响应呼叫**：接收 2.5 的呼叫通知，进入目标桌以管理态处理。

> 判罚依据参考世界桥牌规则：程序性违规可判程序罚分（规则 90）；可暂停/取消选手当前节次资格（规则 91）；队式赛可判调整分（规则 86）；裁判可裁定某副取消并按规则赋分。

### 6.9 队式赛转播观战（V0.4 新增）
1. 队式赛可开启转播（牌室配置项）；旁观者通过"转播观战"入口进入。
2. 可切换观看各桌（不看手牌，看明手与叫牌出牌），并显示**跨桌实时对比栏**（各桌当前副进度、定约、结果对比）。
3. 手牌不可见规则沿用 6.6；转播数据由服务端推送，延迟可控。

## 7 计分功能

### 7.1 计分模式（插件化）
1. **合约分**（每副必算）：花色等级、墩数、成局/小满贯/大满贯奖分、宕分、加倍/再加倍修正。
2. **MP（比赛分）**：同一副牌多桌/多对结果横向比较排名；单桌场景不适用时自动隐藏。
3. **IMP（国际比赛分）**：队式赛跨桌同副分差换算 IMP，计入队总分。

### 7.2 计分引擎规则
1. 每副结束自动计算本副得分，计入南北/东西（或红蓝队）累计。
2. **手动修正**：室主可改；管理员可改（裁判调整分）。均须填写原因，记录修改前后值、操作人、时间戳。
3. 展示：实时当前副得分 + 各方累计；队式赛显示跨桌比对与 IMP；结束后生成完整成绩单（每副定约、庄家、首攻、结果±墩、南北/东西得分、IMP/MP 汇总）。
4. 对局记录与回放在线保存 **1 年（自盘结束起）**，可导出；到期清理与提醒见 9.6。

### 7.3 队式赛跨桌结算
各桌打完当前副后按同副结果比对换算 IMP；某桌未完成时等待或按超时规则处理；结算结果实时展示。

### 7.4 导出
1. **格式**：JSON 事件流（可重放）、PBN（单副/整盘牌型与叫牌出牌）、CSV 成绩单（UTF-8 BOM，含每副明细与 IMP/MP 汇总）。
2. **方式**：单盘同步导出；全量/历史异步导出，完成后通知下载。
3. **权限**：玩家只能导出自己参与的对局；管理员导出任意对局需填写原因并写审计；被注销/匿名化的账号数据按 9.6 处理。
4. **时点**：与 6.7 一致——同一 `Deal` 所有桌完成后才可导出该副，整盘在 `Session` 结束后才可导出；对局中禁止导出未完成牌。
5. 大厅“最近对局记录”可查询并导出本人参与的对局；成绩单字段与界面展示一致。

## 8 权限与安全
1. **所有访问均需登录**（含旁观与聊天）；旁观者仅观战，不可见手牌、不可参与叫牌出牌。
2. 分数修改仅室主（常规）与管理员（裁判调整分），留完整日志。
3. 密码使用强哈希存储；会话 Cookie 为 `httpOnly + Secure + SameSite=Lax`；登录失败按账号 + IP 锁定；注册、昵称可用性查询、导出接口均限流。
4. 用户名/昵称按 2.1 归一化后唯一；公开界面只显示昵称，用户名/邮箱仅本人和管理员可见；改名受 3 次上限、24h 冷却、对局中锁定和旧名 30 天保留约束。
5. 管理员操作全部留痕（操作人、时间、原因、前后状态），**审计日志至少保存 3 年，只追加、不可由管理员删除**；查看暗手、导出数据等敏感操作同样留痕。
6. WS 校验 Origin，HTTP 接口校验 CSRF；敏感词过滤覆盖聊天、昵称与提醒内容；单 IP/设备连接数限制防刷。
7. 导出/回放必须在服务端做时点与归属鉴权（见 6.7/7.4），不能只靠前端隐藏按钮。

## 9 非功能需求

### 9.1 实时性
操作广播 ≤ 200ms（目标值）；AI 单步决策 ≤ 2s；超时倒计时服务端权威计时。

### 9.2 平台
**仅网页端**，暂不适配移动端；架构不排斥未来响应式改造，但不在当前交付范围。

### 9.3 数据与持久化
1. 对局记录、分数、日志、回放、账号与管理员操作全部服务端持久化；稳定 `userId` 贯穿账号、座位、对局、成绩单、回放与审计。
2. 对局事件流 + 快照支持按 `lastSeq` 重连与断点回放；服务重启后可恢复进行中的全 AI 对局。
3. 在线留存期按 9.6 执行；到期清理前 30 天提示用户导出。

### 9.4 异常处理
掉线保留座位、超时按配置接管；全 AI 对局服务端驱动不依赖前端；注册/改名/导出等写操作失败时返回明确错误码，不产生半完成状态。

### 9.5 可配置（系统管理员）
超时时长、降智档位、等候区上限、牌室销毁超时、举手超时、注册开关/验证码开关、留存期提醒阈值等。

### 9.6 数据留存与导出

| 数据类型 | 保留期 | 说明 |
|---|---|---|
| 对局事件/回放/成绩单 | 盘结束起 **365 天** | 到期前 30 天提醒可导出 |
| 管理员审计日志 | 至少 **3 年** | 只追加，不可由管理员删除 |
| 牌室/大厅聊天 | **90 天** | 敏感词/举报证据可单独留存 |
| 登录/IP/安全日志 | **180 天** | 限流、封号、争议调查 |
| 账号资料 | 至注销或 **2 年未登录** | 连续未登录先提醒 |
| 备份 | 滚动 **30 天** | 删除数据可能短暂存在于备份 |
| 用户导出文件 | 用户自行保管 | 不受服务端留存控制 |

1. 对局/成绩单/回放导出格式与权限见 7.4；单盘同步、全量异步。
2. 注销：30 天冷静期；期满后账号资料匿名化/删除，对局数据按 1 年策略匿名化/删除。
3. 到期清理任务需记录审计；备份中的过期数据随滚动 30 天自然淘汰。
4. **演示期功能**：“推荐 + 浮动层解释”前 50 副试用仅保存在本机浏览器，不属于账号数据，也不随账号同步；接入正式会员体系前不产生付费、订阅或跨设备权益。

## 附录 A：V0.5 变更验收要点

1. **用户名边界**：12 位合法用户名注册成功；13 位、数字开头、含非法字符均返回 `USERNAME_INVALID`。
2. **昵称边界**：12 个 ASCII 成功；6 个汉字成功；7 个汉字拒绝；3 汉字 + 6 ASCII（宽度 12）成功；3 汉字 + 7 ASCII（宽度 13）拒绝；1 个字符拒绝。
3. **保留名**：`admin`、`Admin`、`Ａdmin` 均返回 `USERNAME_RESERVED`/`NICKNAME_RESERVED`。
4. **归一化查重**：`Alice` 与 `alice`、`Ａlice` 不能同时注册；昵称同理；并发注册同名只有一个成功，另一个返回 `409`。
5. **改名次数**：第 1–3 次成功，第 4 次返回 `NICKNAME_CHANGE_LIMIT`；失败/被拒不增加次数；成功后再改需等待 24h，否则 `NICKNAME_COOLDOWN`。
6. **旧昵称保留**：改名后 30 天内其他账号不能使用；本人可改回，但消耗一次改名次数。
7. **对局中改名**：用户处于 `starting/playing/paused` 且已落座时改名返回 `NICKNAME_LOCKED_IN_SESSION`；大厅、等候区、旁观时可改。
8. **可见性**：公开界面只显示昵称；用户名/邮箱仅本人和管理员可见；被封号账号的会话立即失效。
9. **留存**：对局/成绩单/回放盘结束起 365 天；审计日志至少 3 年且不可由管理员删除；聊天 90 天；登录/IP 180 天；到期前 30 天提示导出。
10. **导出**：玩家只能导出自己参与的对局；未完成 `Deal` 或 `Session` 拒绝导出；管理员导出写审计；CSV 带 UTF-8 BOM，PBN 可被第三方工具读取。
11. **跨桌隔离**：队式赛对局中，参赛玩家看不到另一桌的定局、结果或进度；旁观/转播按配置延迟。
12. **演示期试用**：非会员前 50 副可用，开始第 51 副时自动关闭且不能再次开启；会员可自由开关；试用进度仅保存在本机，不同步到账号。
